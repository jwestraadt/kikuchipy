# Phase 4 -- `spherical-cross-correlation`: requirements

## Scope

## Decisions

Every "measured" number below comes from the drafting probe -- a faithful NumPy/Numba transcription of `sht_xcorr.hpp` on top of the merged Phase 1-3 modules -- and from a small C++ driver compiled against the EMSphInx headers @ 60f3517 with MSVC 2022 (`/O2`, `EM_USE_D`, the FFTW 3 static library of the EMSphInx build tree); both are recorded in `validation.md`, "Recorded results", and are to be re-measured with the real implementation.

### D1 -- Sizes and array layouts (frozen; `:372-383`, `:155-168`)

- `bandwidth = bw` (exclusive maximum degree, `>= 1`, `ValueError` otherwise), `side_length_unpadded = sl = 2 bw - 1`, **`side_length = slP = _fft.fast_size(sl)`** (the verbatim `fastSize` port, never `scipy.fft.next_fast_len`; the two disagree for most recommended bandwidths, e.g. `next_fast_len(105) = 105` but `next_fast_len(105, real=True) = 108`, `next_fast_len(117) = 120`), **`half_side_length = bwP = slP // 2 + 1`** (`:376`, integer division). Table for the bandwidths this phase tests: `53 -> 105, 54 -> 108, 55 -> 110, 56 -> 112, 57 -> 117, 58 -> 117, 59 -> 117, 60 -> 120, 61 -> 121, 62 -> 125, 63 -> 125, 64 -> 128, 68 -> 135, 88 -> 175, 113 -> 225, 123 -> 245, 158 -> 315` (and `384 -> 770`, the Phase 1 counter-example region). Even `slP` occurs only for padded bandwidths (54, 55, 56, 60, 64 above); the recommended `fast_bandwidths()` are all odd `slP`.
- **No factor-13 warning** (constitution amendment 0.2 in `plan.md`): the constitution says "warn when `slP` has a factor 13" because pocketfft has no radix-13 codelet, but the measured cost is small -- the separable inverse takes 11.1-12.4 ms at `slP` 117 (`= 9 x 13`, `bw` 57-59; the spread is the run-to-run range of the same measurement) against 10.5 ms at 120 and 12.8 ms at 121 (`= 11^2`), i.e. `1.06-1.18x` on the FFT stage, a penalty of 0.6-1.9 ms on a `correlate` of ~17 ms at `bw` 57-59 (kernel ~4.5, inverse ~11.7, peak ~1 ms), i.e. `~4-11 %` -- and `bw` 59 is in `fast_bandwidths()` (`fast_size(117) == 117`), so the warning would fire on a recommended bandwidth. Recorded in the class docstring instead. (Phase 1 never implemented the warning, so the "no warning at `slP` 117" test of `validation.md` is a regression guard, not a determination; the substantive pin is `side_length == fast_size(2 bw - 1)` at `bw` 57-59.)
- **`fxc`** is `(slP, slP, bwP)` complex128 C-contiguous, indexed `[k, n, m]` = the C++ flat `k slP bwP + n bwP + m` (`:381`), half-complex along the *last* axis `m` (alpha). **`xc`** is `(bwP, slP, slP)` float64 C-contiguous, indexed `[k, n, m]` = the C++ flat `k slP slP + n slP + m` (`:382`), i.e. **`k` (beta) slowest, `n` (gamma) middle, `m` (alpha) fastest**, only the first `bwP` beta slices (`beta in [-pi, 0]`, D6). Kept in the C++ order because (i) the flat argmax index is then identical to the C++ `findPeak()` (measured identical for every driver case), (ii) `irfft` along the last axis is the natural c2r, and (iii) Phases 8-9 index the volume as `master_xcorr.cpp` does. Memory: `fxc` `16 slP^2 bwP` bytes, `xc` `8 slP^2 bwP`, `rDen` `8 slP^2 bwP`, the transposed `pi/2` table `8 bw^3`, `fm` `16 bw^2`, `gn` `16 bw`: at `bw` 63 / 68 / 88 / 113 -> `fxc` 15.8 / 19.8 / 43.1 / 91.5 MB, `xc` 7.9 / 9.9 / 21.6 / 45.8 MB, table 2.0 / 2.5 / 5.5 / 11.5 MB (D11 has the measured peaks).
- **Wigner table**: `wigner_d_half_pi_table(bw, transpose=True)` (Phase 3), `table[m, k, j] = d^j_{k,m}(pi/2)`, exactly the C++ `wigD` (`:368`, `dTable(bw, wigD, true)`); the kernel reads `table[m, k, j]` for `fm` (C++ `wigD[m bw^2 + k bw + j]`, `:736-744`) and `table[k, n, j]` (`= d^j_{n,k}(pi/2)`) for `gn` (`wigD[k bw^2 + n bw + j]`, `:762`). Its NaN slots (`j < max(k, m)`) are **never read**: the loops start at `j = max(m, k)` and `j = max(k, n)` (measured: replacing every NaN by `1e300` leaves `fxc` bitwise unchanged at `bw` 8, 9, 12; a named test). Optionally shared between instances via `clone()` (D9). The `dTablePreBuild` factors (`wigE/wigW/wigB`, `:369`) are **not** allocated in this phase (Phase 7 adds them to the shared constants when `derivatives` arrives; measured `2 bw^3` doubles = 5.0 MB at `bw` 68).

### D2 -- The spectrum kernel `_xcorr_spectrum` (faithful transcription of `:699-854`)

`_xcorr_spectrum(flm, gln, table, n_fold, mirror, fxc, fm, gn)`, `@njit(cache=True, nogil=True)`, writes `fxc` in place using the caller-owned scratch `fm (bw, bw)` and `gn (bw,)`:
- Flags as the C++ (`:699-705`): `flmFold = n_fold`, `glnFold = 1`, `fMir = mirror`, `gMir = False`, so `mirror_any = mirror` and `bMirror = False` -- the pattern side never has symmetry; the systemic-zero column mask reduces to `m % n_fold == 0` (`:709-726`; the `nonZero0/1` parity split is dead when `bMirror` is false and is not reproduced -- the kernel tests `m % n_fold` directly).
- Per slice `k < bw`: `fm[m, j] = flm[m, j] table[m, k, j]` for `j >= max(m, k)`; per row `n < bwP`: if `n < bw` (`n % glnFold == 0` is always true), `gn[j] = conj(gln[n, j]) table[k, n, j]` for `j >= max(k, n)`, then per column `m < bw`: if `m % n_fold == 0`, `start = max(m, k, n)`; **mirror branch** (`:773-783`): `if (start + m) % 2: start += 1`, `toggle = (start + m) % 2 == 0`, sum `j = start, start + 2, ...` of `vp = fm gn`, `vc = fm conj(gn)` (`conjMult`: `rr - ii`, `ir + ri`, `rr + ii`, `ir - ri`), `vnc = -vnc if not toggle` -- **this negation is dead code**: with `gMir == false` the branch is entered only when `fMir` is true, `:774` has just made `(start + m)` even, so `toggle` (`:776`) is always true and `:783` never fires; the port keeps the two lines for fidelity, marks them `# pragma: no cover` with a comment citing `:774-776`/`:783`, and they are excluded from the coverage target (a mutation of them is unkillable and is not in the bug-injection list); **plain branch** (`:784-793`): `toggle = (start + m) % 2 == 0`, `v += vp`, `vnc += vc if toggle else -vc`, `toggle` flips per `j` (this seed *is* live and *is* in the list); then `if k % 2: vnc = -vnc` (`:794`); `match = (m + n) % 2 == 0`; the **four slots** (`:796-817`): `fxc[k, n, m] = v`; `fxc[slP-k, slP-n, m] = vnc` (only `k > 0 and n > 0`); `fxc[slP-k, n, m] = +-v` and `fxc[k, slP-n, m] = +-vnc` with `+` if `match` else `-` (only `k > 0` resp. `n > 0`). The C++ writes the last two through `if posK ... else if posN` inside `!posKN`, which is the same set of writes because at most one of them is true there.
- **Systemic zeros are written, not assumed** (`:818-829`, `:831-837`): the columns `m % n_fold != 0` are written as `0` in all their (up to four) slots for `m < bw` (the C++ column loop `:766` runs to `mBw = bw`), the rows `n >= bw` (and, generally, `n % glnFold != 0`) are zero-filled over the **full** `bwP` columns (`std::fill`, `:833-836`), and the zero-pad slices `k in [bw, slP - bw]` are zeroed after the loop (`:854`; slice `slP - bw` is not touched by the loop, so the inclusive upper end is right). Consequence: **`fxc` may be reused across calls with different `n_fold`/`mirror`** -- every slot the kernel does not write is a column `m in [bw, bwP)` of a row `n < bw`, which nothing ever writes and which is zero from allocation (`np.zeros`, matching the C++ value-initialised `fft::vector`; verified bitwise: fresh vs reused `fxc` at `bw` 9 / `slP` 18 / `bwP` 10 after `(3, True)` then `(1, False)`). Zeroing on top of the faithful writes would only cost time (a 20 MB memset per call at `bw` 68). Note for the reviewer: on a `np.zeros` buffer the pad-slice write is a no-op that the buffer-reuse and systemic-zero tests cannot see -- the pad-region *garbage* test of `validation.md` (pre-fill `fxc[bw:slP - bw + 1]` with a non-zero value, then `compute` equals a fresh instance bitwise) is what pins it.
- Complex arithmetic only (no transcendental functions), so the compiled kernel and its `.py_func` are bitwise equal on this machine (measured 0.0 at `bw` 8, 9, 12); the test pins `abs <= 4 eps max|fxc|` (CI lesson: LLVM may contract differently on another host). `conj` is spelled `.conjugate()` (numba 0.57 floor).
- Measured against the compiled C++ (`validation.md`): `max |xc - xc_cpp| / max |xc_cpp|` = 1.7e-16 to 2.9e-16 for `(bw, n_fold, mirror)` in `{(16, 1, F), (17, 1, F), (16, 3, T), (17, 4, F), (17, 2, T), (24, 6, T), (53, 1, F)}`, the argmax index identical in all seven, the interpolated ZYZ identical to `4.4e-16`, the peak value to `2.8e-16` relative -- so the transcription is settled; the analytic oracles of D4 guard the port against a *shared* misreading of the C++.

### D3 -- The inverse FFT (`SepRealFFT3D::inverse`, `fft.hpp:671-678`, with `scipy.fft`)

- What the C++ does: for every `m` plane with `m % dx == 0` (`dx = flmFold`, `:857`): a full-length backward DFT along `k` for all `n`, then a backward DFT along `n` **for the first `bwP` values of `k` only** (`howmany = vH`, `fft.hpp:630`), written back into `spectra`; then `c2r` along `m` for `k < bwP` (`:677`). Everything unnormalised (FFTW), sign `+i`.
- Port, `_inverse_fft(fxc, n_fold) -> xc`: `t = scipy.fft.ifft(fxc[:, :, ::n_fold], axis=0, norm="forward", workers=1)[:bwP]`; `t = scipy.fft.ifft(t, axis=1, norm="forward", workers=1, overwrite_x=True)`; scattered back into a zero `(bwP, slP, bwP)` complex buffer at `[:, :, ::n_fold]` when `n_fold > 1` (no scatter, i.e. no extra buffer, when `n_fold == 1`); `xc = scipy.fft.irfft(t, n=slP, axis=2, norm="forward", workers=1, overwrite_x=True)`. `norm="forward"` makes both inverse transforms unnormalised, i.e. FFTW's `c2r`; `workers=1` always (constitution). **The plane skipping is implemented now** (measured 17.3 -> 11.1 ms at `bw` 68 with `n_fold` 4, 60.6 -> 33.5 ms at `bw` 88, 136.5 -> 71.8 ms at `bw` 113; it is exact because the skipped planes are the zeros the kernel wrote). Reference identity, a named test at `bw in {16, 17, 24, 53}` for `n_fold in {1, 3, 4, 6}`: `_inverse_fft(fxc, n_fold) == scipy.fft.irfftn(fxc, s=(slP, slP, slP), axes=(0, 1, 2), norm="forward", workers=1)[:bwP]` to `abs 1e-12 max|xc|` (measured `<= 3e-16` relative; both agree with the C++ to the same level); plane skipping vs no skipping (`n_fold` 1 passed to `_inverse_fft` on the same zero-planed `fxc`) to `abs 4 eps max|xc|` (measured 0.0, but the two are different `pocketfft` call shapes -- strided sub-array vs contiguous -- so bitwise is not asserted; CI lesson). The full `irfftn` is 1.4x (bw 53) to 2.6x (bw 113, `n_fold` 4) slower and materialises the whole `slP^3` cube (its `[:bwP]` view keeps 19.7 MB resident at `bw` 68 instead of 9.9), so it stays a test oracle. **Memory does not tell the two inverses apart** (measured, D11): `irfftn` transforms in place along the first two axes and allocates only the real cube (`+19.7` MB transient at `bw` 68 vs the separable path's `+29.7`), and a full-cube implementation that copies its `[:bwP]` slice is byte-for-byte the separable path's footprint; the separable structure is therefore pinned functionally -- the FFT-call recording test of `validation.md` (`ifft`, `ifft`, `irfft` per `compute`, no `*n` transform) -- and by the timing baseline, not by a memory bound.
- Transient memory of the separable path (measured with `tracemalloc`, `n_fold` 1): the `ifft` along `k` returns a full `(slP, slP, bwP)` complex array (as large as `fxc`) before the `[:bwP]` slice, so a `correlate` call on a warm instance peaks `+23.6 / +29.7 / +64.7 / +137.3` MB above the resident buffers at `bw` 63 / 68 / 88 / 113 (D11 table). Recorded as an optimisation target (transform along `k` plane by plane, or trim with `overwrite_x` semantics), not done now: the recurring per-thread peak at `bw` 68 is 62 MB (un-normalised) / 72 MB (normalised, D11).

### D4 -- What `compute()` computes (determined by oracle, then frozen in the docstring)

- **Closed form** (measured, the only one of four candidate index/conjugation placements that matches): for the Euler grid of D6, `xc[k, n, m] = sum_l sum_{m'=-l}^{l} sum_{n'=-l}^{l} f^l_{m'} conj(g^l_{n'}) wigner_D(l, n', m', zyz(k, n, m))` with Phase 3's `wigner_D(j, k, m, zyz) = d^j_{k,m}(beta) exp(i (m alpha + k gamma))` and the negative orders `a^l_{-m} = (-1)^m conj(a^l_m)`; i.e. `xc = sum f^l_{m'} conj(g^l_{n'}) d^l_{n',m'}(beta) exp(i (m' alpha + n' gamma))`. Measured at `bw` 6 / 8 / 8 (`n_fold` 2, mirror): `max |oracle - xc| = 1.07e-14 / 1.51e-14 / 1.39e-14` on 60 grid points each (scale 12.4 / 14.6 / 7.6), while the other three placements (`wigner_D(l, m', n')`, and either conjugated) differ by 9.4-17. Frozen as **the triple-sum oracle**, `abs <= 1e-11` (scale-free margin > 500x), at `bw in {6, 8}` for `(n_fold, mirror) in {(1, F), (2, T), (3, F)}` on 60 grid points including `k = 0`, `k = bwP - 1`, `n, m in {0, slP - 1}`.
- **Equivalently** (the cheaper oracle, and the interpretation): `xc[k, n, m] = <rotate_harmonics(flm, zyz(k, n, m)), gln>` with the real inner product `sum_l [Re(a^l_0 conj(b^l_0)) + 2 sum_{m>0} Re(a^l_m conj(b^l_m))]` (Phase 1 normalisation: `4 pi` times the mean of the product of the two real functions). Measured worst `5.7e-14 / 4.3e-14 / 1.8e-13 / 8.6e-13` at `bw` 16 / 24 (`n_fold` 4, mirror) / 32 (`n_fold` 3) / 68 (`n_fold` 4, mirror) on 40 random grid points (relative `<= 1.2e-14`); frozen as **the inner-product oracle**, `abs <= 1e-12 max|xc|`, at `bw in {16, 24, 32}` (68 weekly). Since `rotate_harmonics` satisfies `g_R(n) = f((~R) n)` (Phase 3), `xc(zyz) = 4 pi <f((~R) .), g>` with `R = Rotation(zyz_to_quaternion(zyz))`: **the correlator returns the `zyz` for which `gln == rotate_harmonics(flm, zyz)`**, and `correlate(flm, rotate_harmonics(flm, zyz0))` peaks at `zyz0` with the peak value equal to the total power `<f, f>` (measured exactly for the value of the oracle at `zyz0`: `20.430778 / 33.341807 / 9.196171` at `(bw, n_fold, mirror) = (6, 1, F) / (8, 1, F) / (8, 2, T)`, the three cases of the peak-identity test). **On-grid rotations are recovered exactly**: for `zyz0 = index_to_euler(knm)` the autocorrelation identity `C(Q) = C(Q^-1)` makes the two axis neighbours of the peak cell equal in each of the three directions, so the Newton step from `x = 0` is zero, `zyz == zyz0` and `score == power` to rounding (measured `|x| <= 2e-16`, `score/power = 1 + 2e-16` for three cells x five seeds at `bw` 8) -- this is the doctest example of `plan.md`. At the boundary the orientation is `_euler.rotation_from_zyz(zyz) == ~R` (sample -> crystal), **provisional until Phase 5** as Phase 3 recorded; the tests of this phase use `zyz_to_quaternion` explicitly and never `rotation_from_zyz`, so a Phase 5 flip changes no Phase 4 test.
- **Symmetry side** (needed by every symmetric test): a master `f` with `rotate_harmonics(f, S) == f` for the point-group operators `S` about z gives `rotate_harmonics(rotate_harmonics(f, S), zyz) = rotate_harmonics(f, zyz(Q Q_S))` (Phase 3 composition, later rotation on the left), so the equivalent solutions are `Q Q_S`, i.e. `~(Q Q_S) = ~Q_S ~Q` -- **the symmetry sits on the left of `~Q`**, which is where orix' `Orientation(rotation.data, symmetry)` puts it (verified: `Orientation((s * r).data, C4).angle_with(Orientation(r.data, C4)) == 0` while `(r * s)` gives 43 deg). The misorientation metric of every test is therefore **`Orientation((~Rotation(zyz_to_quaternion(zyz_true))).data, symmetry).angle_with(Orientation((~Rotation(zyz_to_quaternion(zyz_found))).data, symmetry), degrees=True)`** with orix' `_groups` symmetry of the point-group name (`C1` for the symmetry-free cases). Measured: without the reduction the symmetric-group results are 179.7-180.0 / 120 / 90 / 60 deg apart (the C++ `pg.disoQu` step), with it 0.20-0.76 deg over `bw` 53-63.

### D5 -- Peak finding, neighbourhood, interpolation (`:394-432`, `:505-544`, `:862-876`, `:1261-1366`)

- `_find_peak(xc) -> int` is the C++ loop (`:868-874`): first strict maximum in C order (`>`, so among tied maxima the **smallest flat index** wins -- pinned by a test with deliberate duplicates, since a `>=` mutation would survive every random cube), NaN-skipping; the normalised path uses `_scale_and_find_peak(xc, r_den) -> int`, the fused in-place `xc *= rDen` with running argmax of `:1146-1154` (no temporary; the C++ order of operations). Both `@njit(cache=True, nogil=True)`; `np.argmax` is not used because its NaN semantics differ (first NaN wins).
- `_extract_neighborhood(xc_flat, slP, bwP, k0, n0, m0, emsphinx_compatible, nh)` (the flat `xc.reshape(-1)` view, see below): the `3 x 3 x 3` block with periodic wrap in all three index arrays (`:513-524`), then the **glide** for the slots whose `k` lies in the unstored half (`k >= bwP`, only reachable when `k0 == 0` or `k0 == bwP - 1`, `:527-533`). **`emsphinx_compatible=True` (default) reproduces the C++ literally**, which is *two* documented defects (recorded here, new -- neither is in `explore-emsphinx-core-algorithm.md` section 8): (i) the alpha/gamma shift is applied **per slot index `i`** (`inds[2][i]`, `inds[1][i]`) and not per glided *plane*, so when the `k + 1` (or `k - 1`) slot is glided, the *`n = i` and `m = i` slots of all three planes* are shifted while the *other* slots of the glided plane are not; (ii) for even `slP` the shift `x < bwP ? x + bwP - 1 : x - bwP` -- applied identically to the alpha slot `inds[2][i]` (`:530`) **and the gamma slot `inds[1][i]`** (`:531`) -- is `+slP/2` for `x < bwP` but `-slP/2 - 1` for `x >= bwP` (off by one; gotcha 12), and at `x = bwP - 1 = slP/2` it produces `slP`, one past the axis: an `m` slot of `slP` reads the *next row's* first element (flat offset `k slP^2 + (n + 1) slP`), an `n` slot of `slP` reads the *next beta slice's* row 0 (flat offset `(k + 1) slP^2 + m`), both silently in-buffer in the C++, **except at `k0 = bwP - 1`, where the glided plane's shifted `n` slot combined with the centre `k` slot reaches offsets `>= bwP slP^2`, past the end of `xc`** (enumerated over `k0 in {0, bwP - 1}` and all `(n0, m0)`: `slP` 32 / 108 / 128 -> 64 / 216 / 256 triples with an `m` slot of `slP`, the same number with an `n` slot of `slP`, and 35 / 111 / 131 triples reading past the end, up to `slP + 1` elements: exactly `(k0, n0, m0) = (bwP - 1, bwP - 2, any m0)` -- three slots past the end -- plus the three triples `(bwP - 1, n0, bwP - 2)` with `n0 in {0, bwP - 3, slP - 1}`, one slot past the end; odd `slP`: none). The port reproduces the in-buffer *values* by reading the flat buffer at the same offset (`xc.reshape(-1)[...]`, never a 3-D index; that is why the neighbourhood kernel takes the flat view) and **bounds every flat offset with `min(offset, size - 1)`**: the past-the-end values are undefined behaviour in the C++ (unspecified, allocation-dependent) and are therefore **never asserted against the C++ driver or a literal transcription -- only the in-buffer, out-of-row/out-of-slice reads are**; the clamped slots are documented and their positions pinned (`validation.md`). Measured effect on the neighbourhood (relative to `max |xc|`, against the periodic block of the *full* `slP^3` cube from `irfftn`, clamped reads): 0.32 / 0.35 (`bw` 16, `k0` 0 / `bwP-1`; exhaustive over all 1024 `(n0, m0)`: 0.50 / 0.43), 0.091 / 0.082 (`bw` 60; exhaustive 0.124 / 0.110), 0.35 / 0.25 (`bw` 17), 0.088 / 0.092 (`bw` 63), 0.106 / 0.099 (`bw` 53); interior `k0`: exactly 0. Both settings are pinned by tests; the docstring names the two C++ defects with line numbers.
- `_interpolate_maxima(p, x) -> float`: literal transcription of the 27 tri-quadratic coefficients `a_{kji}` (`:1265-1308`), Newton with the analytic 3x3 Hessian, `maxIter = 25`, `eps = sqrt(machine eps)`, reset to `x = 0` when not converged (`:1350`), and the C++ `vPeak` expression at `x` (`:1354-1364`) (corrected 2026-08-17: `vPeak` is **not** the fitted value at `x` -- a *third* C++ defect, found while applying the test-quality review. Its three mixed cubic terms are evaluated at the wrong monomials, `a112 * xy * x[2]`, `a211 * yz * x[0]` and `a121 * zx * x[1]`, which all reduce to `z y x` instead of `z y x^2`, `z^2 y x` and `z y^2 x`; the Hessian `:1318-1323` and the gradient `:1335-1337` use the correct monomials, so `x` is the stationary point of the full fit and only the returned value deviates, by 1.2e-7 to 6.1e-7 on the random 27-coefficient blocks measured below and by exactly 0 whenever those three coefficients vanish, as they do for every separable quadratic. The port is faithful, i.e. bitwise equal to the C++ `vPeak`, and the defect is documented in `_interpolate_maxima`'s `Notes` and in the module docstring next to the other two); `p` is `[k, n, m] = [z, y, x]` and `x = (dk, dn, dm)`. **The kernel is `@njit(cache=True, nogil=True, error_model="numpy")`** (the one deviation from the project's default flags, constitution amendment 0.8): the C++ divides the six cofactors by `det` with no guard (`:1319-1325`) and relies on IEEE semantics -- on a flat block (`det == 0`, e.g. every value equal) the step is NaN, `maxStep < eps` stays false for 25 iterations and `:1350` resets `x = 0`, so the centre value is returned; Numba's default `error_model="python"` raises `ZeroDivisionError` there instead (measured: `@njit(cache=True, nogil=True) def div(a, b): return a / b` -> `div(0.0, 0.0)` raises; with `error_model="numpy"` -> `nan`; the drafting probe's default-model kernel raised on `np.full((3, 3, 3), 2.5)`, the `numpy`-model kernel returned `2.5, x = 0`, and both agree bitwise on 200 random blocks). Flat neighbourhoods are reachable in production (a masked pattern with an empty region, an all-zero `gln`, a rotation-invariant spectrum), so this is a correctness fix, not a nicety. Arithmetic only, `.py_func` bitwise here on generic blocks (measured), but the assertion is `|x_compiled - x_py| <= 1e-9` (a fraction of the `sqrt(eps) ~ 1.5e-8` stopping rule -- one differing FMA contraction can change the iteration count) and the value to `rel 1e-12`; the `.py_func` is driven with NumPy arrays only (its flat-block behaviour depends on the scalar type: `np.float64` gives the NaN path with `RuntimeWarning`s, a Python `float` raises), under `np.errstate(divide="ignore", invalid="ignore")`. Exact on synthetic separable quadratics: measured recovery of `(0.3, -0.2, 0.45)`, `(0, 0, 0)`, `(0.49, 0.49, -0.49)` to 12 digits with the value 5.0 exact.
- `interp_peak` (`:406-432`): `x_max = max(|x[0]|, max(|x[1]|, |x[0]|))` when `emsphinx_compatible=True` -- **the documented `x[2]` bounds bug** (`:421`; gotcha 11): an alpha over-step is never caught -- and `max(|x[0]|, |x[1]|, |x[2]|)` when `False`; `if x_max > 1: x = 0, peak = p[1, 1, 1]`; then `alpha = ((m + x[2]) 4 - slP) pi / (2 slP)`, `beta = ((k + x[0]) 2 - slP) pi / slP`, `gamma = ((n + x[1]) 4 - slP) pi / (2 slP)`. Pinned by a synthetic block with its maximum at `x = (0.2, 0.1, 1.5)`: faithful returns `x` unchanged (alpha 1.5 cells beyond the centre) and the fitted value, exact resets to the centre; a block with the maximum at `(1.5, 0.1, 0.2)` resets in both, and one at `(0.1, 1.5, 0.2)` resets in both (the `x[1]` term, so that a mutation of either surviving term is killed). Consequence for the result range: with `emsphinx_compatible=True` only `beta` and `gamma` are bounded by the check; `alpha` is unbounded in principle (D7). In the random-rotation suites `|x| > 1` never occurred (max `|x|` 0.56 over 460 correlations), so the bug is dormant there.
- **The one keyword `emsphinx_compatible`** (constitution: quirks behind explicit per-call keywords, never module globals) covers both the neighbourhood glide and the `x[2]` check, default **`True`** (faithful; the Phase 6/7 parity runs use it, and Phase 10 compares against `IndexEBSD.exe`).

### D6 -- Euler grid <-> index (`:549-590`)

- `index_to_euler((k, n, m), slP)`: `alpha = (4 m - slP) pi / (2 slP) = 2 pi m/slP - pi/2`, `beta = (2 k - slP) pi / slP = 2 pi k/slP - pi`, `gamma = 2 pi n/slP - pi/2` (constitution). Stored `k in [0, bwP)` covers `beta in [-pi, 0]` (odd `slP`: up to `-pi/slP`, so `beta = 0` is between the last stored slice and its glide image; even `slP`: `beta = 0` is slice `bwP - 1`).
- `euler_to_index(zyz, slP) -> (k, n, m)`: **first** `beta = _euler.wrap_beta(beta)` (into `[-pi, pi]`; the constitution's rule for every beta-taking entry point, applied here as a documented addition to the C++ exactly as Phase 3 did for `wigner_D` -- the C++ formula on an unwrapped `beta`, e.g. `pi + 0.1` at `slP` 135, gives `kR = 137.15 -> slP - kR = -2.15 -> k = -2`, a `size_t` wrap in C++ and a silent index-from-the-end in Python; Phases 6 and 8 will pass arbitrary ZYZ triples) and `alpha`, `gamma` into the grid's own range `[-pi/2, 3 pi/2)` (`(x + pi/2) % (2 pi) - pi/2`, the same rotation, so that `nR`, `mR` are non-negative before rounding), then the C++ formulas: `kR = ((beta slP)/pi + slP)/2`, `nR = ((gamma 2 slP)/pi + slP)/4`, `mR = ((alpha 2 slP)/pi + slP)/4`; `if kR > slP/2: kR = slP - kR; nR = fmod(nR + slP/2, slP); mR = fmod(mR + slP/2, slP)`; then rounding with **`floor(x + 0.5)`** (C++ `std::round` on non-negative arguments; Python's banker's `round` differs at `.5`); the returned `n`, `m` are reduced modulo `slP` (the C++ leaves e.g. `alpha = 3 pi/2 - tiny` at `m = slP`, an out-of-range index it never uses -- `eulerIndex` has no caller in EMSphInx). Pinned: `euler_to_index((a, pi + 0.1, g), 135) == euler_to_index((a, -pi + 0.1, g), 135)` (the wrapped equivalent) and `0 <= k < bwP`, `0 <= n, m < slP` for 200 random unwrapped triples (`beta` uniform in `[-4 pi, 4 pi]`, `alpha`, `gamma` in `[-3 pi, 3 pi]`), each mapping to the same index as its wrapped equivalent. **Recorded corner**: for odd `slP` and `beta` exactly `0 (mod 2 pi)`, `kR = slP/2` is not glided (`>` is false) and rounds to `bwP`, outside the stored half; the port clamps `k` to `bwP - 1` (documented; the C++ would index outside the cube; a test pins `euler_to_index((0, 0, 0), 135) == (67, 34, 34)`). Round trips measured: `euler_to_index(index_to_euler(knm)) == knm` exactly on every stored `k` and the sampled `n, m` for `slP in {32, 33, 105, 120, 135}`; `euler_to_index` of a random rotation, converted back, is at most `2.97 / 2.82 / 2.62` deg away at `slP` 105 / 120 / 135 and `10.05 / 11.38` deg at `slP` 32 / 33 (the half-cell body diagonal `sqrt(3) 180/slP` is 2.97 / 2.60 / 2.31 / 9.74 / 9.45; the excess is the `alpha + gamma` coupling near `beta = 0`), pinned as **`<= 1.5 sqrt(3) 180/slP`** (measured worst ratio 1.20 at `slP` 33, 1.14 at 135). **Note on the sign of `beta`** (so that nobody reads a failing test as a sign error): `quaternion_to_zyz` returns `beta in [0, pi]` (measured 0.054-3.093 over 2000 draws), i.e. every random test rotation lies in the *unstored* half and is recovered as its glide image with `beta <= 0` -- `euler_to_index` glides it, `correlate` returns the glided triple, and the misorientation metric of D4 (quaternions) is blind to the choice; the same holds for the peak-identity `zyz0 = (0.7, 1.1, -2.3)`.

### D7 -- `correlate()`: signature, returns, semantics

- `SphericalCrossCorrelator.correlate(flm, gln, n_fold, mirror, *, refine=False, emsphinx_compatible=True) -> (zyz, score)`; `refine=True` raises `NotImplementedError` naming Phase 7 (`spherical-refinement`); `zyz` is a `(3,)` float64 array in radians; **its range depends on the keyword** (the interpolation may step one cell outside the grid; `cell = 2 pi/slP`): with `emsphinx_compatible=False` the full `|x| <= 1` check gives the closed intervals `alpha, gamma in [-pi/2 - cell, 3 pi/2]` and `beta in [-pi - cell, cell]` (`x[1] = 1` at `n = slP - 1` is exactly `3 pi/2`; odd `slP` reaches only `cell/2` in `beta`), asserted on every result of that setting; with the default `emsphinx_compatible=True` only `beta` and `gamma` are bounded (the `x[2]` bug of D5 leaves `alpha` unchecked, so `alpha` is finite but unbounded in principle -- D5's own pinned block returns `x[2] = 1.5`), asserted as the `beta`/`gamma` intervals plus `np.isfinite(alpha)`, with `max |x[2]|` over the suite recorded (`record_property`; measured 0.56 over 460 correlations); `score` is the interpolated peak (D5) of the raw sum of D4 -- **the un-normalised metric**: equal to the total power `<f, f>` for a perfect match, scaling with both spectra, comparable only within one geometry (measured on random white spectra: interpolated peak/power 0.85-0.92 for an *off-grid* rotated copy because the tri-quadratic under-estimates a peak that is one cell wide, exactly 1 for an on-grid one (D4); 0.994 for the Ni master). **`compute()` allocates and returns a fresh, caller-owned `(bwP, slP, slP)` array on every call** (the `irfft` output; `scipy.fft` has no `out=`), and rebinds the instance's `xc` attribute (the "last result" that `interp_peak` reads) to it -- so a result kept by the caller stays valid across later calls (D8 relies on this: `mrf` is kept while `mrf2` is computed; a test asserts two successive results are distinct objects and the first is bitwise unchanged after the second call). The C++ instead takes an explicit output pointer (`compute(..., Real* pXc)`, `:658`; `:1191` writes into `rDen.data()`, `:1194` into `cor->xc.data()`); an `out=` parameter is not offered because it would only add a copy.
- Argument order `(n_fold, mirror)` follows `_symmetry.point_group_flags` (the C++ `compute` takes `(fMr, fNf)` -- reversed -- so `n_fold` is validated as an `int` that is not a `bool` and `>= 1`, and `mirror` as a `bool`, `ValueError` otherwise, which makes a swapped call fail loudly). `flm`, `gln` are cast with `np.ascontiguousarray(..., complex128)` and must be `(bw, bw)` (`ValueError`); the rows `m % n_fold != 0` and, with `mirror`, the entries with `l + m` odd are **assumed** zero and skipped (documented precondition, as in EMSphInx; `MasterPatternHarmonics` already validates its flags against the coefficients).
- **Ranges of the coarse error, measured, then pinned** (band-limited random pairs on the Legendre grid, D10): the tri-quadratic result is within **half a grid cell** (`180/slP` deg, symmetry-reduced) except when the true `beta` is within one cell of `0` or `pi` (D5's neighbourhood defects), where it is within one cell.

### D8 -- `NormalizedSphericalCrossCorrelator` (`:236-270`, `:1128-1204`)

- Constructor `(bandwidth, flm, flm2, n_fold, mirror, mlm)`: owns a `SphericalCrossCorrelator(bandwidth)`; copies `flm`, `flm2`, `mlm` (validated as above); computes `mrf = compute(flm, mlm)` (kept -- a fresh array, D7), `mrf2 = compute(flm2, mlm)`, `s2m = mlm[0, 0].real sqrt(4 pi)` ("assumes the window function is a binary mask", `:1197`; with Phase 1's normalisation this is `4 pi <mask>`, the solid angle of the window), `fWbar = mrf / s2m` (Huhle eq. 9), **`rDen = 1 / sqrt(mrf2 - 2 fWbar mrf + fWbar^2 s2m)`** (eq. 8, `:1200`), computed **in place** on the two `xc`-sized arrays (no third temporary: `mrf` is squared in place, scaled by `1/s2m`, subtracted from `mrf2`, `sqrt` and reciprocal in place -- measured construction peak 49 / 62 / 135 / 286 MB at `bw` 63 / 68 / 88 / 113, i.e. `1.47x` the analytic `fxc + xc + rDen + table`, against 65 / 82 / 178 / 378 MB for the drafting probe's non-in-place arithmetic, D11) and stored read-only. Both `compute` calls use the master's `(n_fold, mirror)` as the C++ does (`:1191`, `:1194`): the mask has no symmetry but only the *first* function's flags enter the loop bounds. No guard against a non-positive radicand (the C++ has none; the radicand is `s2m Var_window(f) >= 0` mathematically). Consequences, stated precisely: a *negative* radicand gives a NaN slot, which loses every `>` comparison of `_scale_and_find_peak`; a radicand of exactly **zero gives `rDen = +inf`, and `xc * inf` is `+inf` for a positive `xc`, which *wins* the argmax and yields a garbage peak** (an all-`inf` neighbourhood, NaN Newton steps, the reset of D5) -- a zero radicand means `f` is constant over the window, i.e. a caller error (Phase 5 owns `flm2`/`mlm`); documented in the class `Notes`, faithful to the C++, and a `flm2` that is not `SHT(f^2)` produces NaNs -- documented, and a test asserts the wedge-mask and cap-mask `rDen` are finite and positive everywhere (measured on the C++ driver cases: `rDen` agrees with the C++ to `4.4e-16`-`6.6e-16` relative at `bw` 17 / 24 / 53).
- `correlate(gln, *, refine=False, emsphinx_compatible=True) -> (zyz, score)`: `compute(flm, gln, n_fold, mirror)`, then `_scale_and_find_peak` (in place), then `interp_peak` on the *scaled* cube (the C++ interpolates the normalised values, `:1157`); **the score is the C++ metric**: `xc * rDen` at the interpolated peak, **not divided by the pattern norm** (`Indexer::sum2` is dead, `include/idx/indexer.hpp:315`, written and never read; the C++ docstring `:255` and `:1138` says "still needs to be divided by the standard deviation of the pattern function"), so it is not a bounded NCC and is comparable only within a fixed geometry -- measured 3.71-3.93 for the Ni master in the default `emsphinx_compatible=True` normalisation and 1.37-1.47 with `False` (D7 gate below), 0.50-0.68 for the random wedge cases. `refine=True` raises `NotImplementedError` (Phase 7 adds `refinePeak` + `denominator`, `:1169-1172`, `:1211-1225`).
- **The D7 gate of Phase 2 (measured, decision kept)**: Ni master (`nickel_ebsd_master_pattern_small`, `bw` 68, `n_fold` 4, mirror), `flm2 = analyze(synthesize(flm)^2)` on the Legendre grid `dim` 71 (what `include/modality/ebsd/idx.hpp:275-281` does), the wedge mask (`sht_xcorr.cpp:218-232`, 21.4 % of the sphere) and a 55-deg spherical cap about `(0, -0.5, 0.85)` (21.3 %), four random rotations, `gln = analyze(mask synthesize(rotate_harmonics(flm, zyz)))` (the C++ `testNCorr` recipe): the argmax misorientation (symmetry-reduced, `m-3m`) is 0.12-0.53 deg with `emsphinx_compatible=True` and 0.09-0.47 deg with `False` (half cell 1.33), the per-rotation difference between the settings `<= 0.44` deg, and the scores are `3.71-3.93` (True) vs `1.37-1.47` (False), i.e. **the master's DC term shifts the normalised score by a factor ~2.6 but not the argmax beyond the coarse tolerance**; the default `True` stands. The un-normalised correlator on the same masked `gln` gives 0.10-0.47 deg and score ratios 1.16-1.28 between the settings.
- `clone()` returns a new instance sharing `flm`, `flm2`, `mlm`, `rDen` and the Wigner table (read-only) with fresh `fxc`/`fm`/`gn` buffers (the C++ `clone()` shares `ncLut`/`xcLut`, copies the rest).

### D9 -- Buffers, threads, validation

- A `SphericalCrossCorrelator` instance owns `fxc`, `fm`, `gn` (allocated once) and rebinds `xc` per call; it is **not thread-safe** (documented); `clone()` shares the Wigner table and allocates the rest, and the constructor accepts `wigner_d_half_pi=None` to reuse a table (validated: shape `(bw, bw, bw)`, float64, C-contiguous, the tripwire slot `[0, bw - 1, 0]` NaN when `bw >= 2` -- Phase 3's `out=` idiom, which refuses `np.zeros`/`np.empty` buffers -- and, for `bw >= 2`, slot `[1, 0, 1] < 0`, i.e. `d^1_{0,1}(pi/2) = -1/sqrt(2)` of the transposed layout rather than `d^1_{1,0}(pi/2) = +1/sqrt(2)` of the untransposed one, so a foreign or untransposed table is refused: the two layouts differ by `(-1)^(k-m)` in half of their slots and would silently give a wrong correlation). All kernels are `nogil=True`, so Phase 6's dask threads run their clones in parallel; each thread's transient FFT allocations are its own.
- `bandwidth < 1` -> `ValueError`; a `wigner_d_half_pi` of the wrong bandwidth -> `ValueError`; `interp_peak`/`correlate` before any `compute` -> `RuntimeError`.

### D10 -- Coarse accuracy: measured, tolerance rule (frozen)

Random band-limited pairs (`sht_xcorr.cpp` recipe, `randomSphere`/`randomPair` `:108-170`: uniform(-1, 1) samples on the Legendre grid `dim = bw + (3 if bw % 2 == 0 else 2)` (`:152`, `:218`), `south = north` for a mirror, else an independent south with the equator ring copied from the north (`matchEquator`), `analyze`, exact zeroing of the rows `m % n_fold != 0` (`:160-166`), a random unit quaternion `(|u|, u, u, u)` -> `quaternion_to_zyz`, `gln = rotate_harmonics(flm, zyz)`; **`MasterPattern::makeNFold` (`:124`, the real-space n-fold symmetrisation that precedes the exact spectral zeroing) is intentionally not ported** -- any spectrum with the right systematic zeros serves the assertions, so the generated `flm` is *not* the C++'s and the C++ numbers are not reproduced value for value), coarse path (`emsphinx_compatible=True`), symmetry-reduced misorientation of D4. **The C++ pass criteria are refined-path criteria and are not this phase's**: `testCorr` (`:192`) and `testNCorr` (`:275`) both call `correlate(..., ref = true)`, with `eps = cbrt(float epsilon) = 4.92e-3` deg (`:294`; the in-source comment "~6e-6 degrees for double" is stale -- the code always takes the `float` epsilon), `epsN = 10 eps = 4.92e-2` deg for the normalised tests (`:316`) and `sqrt(eps) 5 = 0.351` deg for the eight point groups (`:345`); the coarse tiers below are ~350x resp. ~5x looser, and Phase 7's validation re-runs these ports against 4.92e-3 / 4.92e-2 / 0.351 deg as its own gate:
