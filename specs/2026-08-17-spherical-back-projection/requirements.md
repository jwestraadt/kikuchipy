## Decisions

Every "measured" number below comes from the drafting probe -- a faithful NumPy/Numba transcription of the C++ listed above on top of the merged Phase 1-4 modules, driven by kikuchipy's `EBSDDetector`, `EBSDMasterPattern.get_patterns` and `nickel_ebsd_small` -- and is recorded in `validation.md`, "Recorded results", to be re-measured with the real implementation. No compiled C++ driver was built for this phase: `detector.hpp` needs HDF5 (`H5Cpp.h`) and the geometry chain is *deliberately* kikuchipy's, not EMSphInx's (D2), so the C++ is a specification for everything downstream of the pixel map (sizes, DCT, weights, normalisation, IQ, preprocessing), which the transcription follows line by line, and kikuchipy's own forward projection is the oracle for the geometry.

### D1 -- `SphericalBackProjector`: signature, attributes, validation (frozen)

- `SphericalBackProjector(detector: EBSDDetector, bandwidth: int, *, signal_mask: np.ndarray | None = None, circular_mask: bool = False, oversampling: float = sqrt(2), dim: int | None = None)`.
  - `bandwidth >= 1` (`ValueError`); `dim` defaults to `_grid.default_dim(bandwidth, "legendre")` (`bw + 2` if odd else `bw + 3`, EMSphInx `gridDim`, `idx.hpp:257`) and is validated by `SphericalHarmonicTransform(bandwidth, "legendre", dim)`, which the instance keeps as **`sht`** (the C++ `Indexer` builds `sht(dim, dim - 2, Legendre)` and analyses to `bw`; ours is constructed at `bandwidth` directly, the same coefficients).
  - **Single PC per call**: the guard is **`detector.navigation_size != 1`** (not `navigation_shape != (1,)`: a legitimate single-PC detector built from a `(1, 1, 3)` array has `navigation_shape (1, 1)` and `navigation_size 1` -- measured -- and must be accepted) -> `ValueError` whose message names `detector.pc_average` and the count ("... has 9 projection centres; back-projection uses one PC per call -- set `detector.pc = detector.pc_average` on a copy (`detector.deepcopy()`), or build a detector from one PC"; `EBSDDetector` is not subscriptable, measured `TypeError`, so the message never says "index the detector"). `nickel_ebsd_small().detector` (pc shape `(3, 3, 3)`) trips it; `detector.deepcopy()` with `pc = pc_average` passes. When the size is 1 but the shape is not `(1,)`, the internal deepcopy's `pc` is reshaped to `(1, 3)` so that `gnomonic_bounds.squeeze()`, `sample_to_detector` and any later call into `_get_direction_cosines_from_detector` (which branches on `navigation_shape == (1,)`, `_master_pattern.py:104`; measured: a `(1, 1)` detector returns `(1, 3600, 3)` there, a `(1,)` one `(3600, 3)`) take the fixed-PC path.
  - **`azimuthal`/`twist` guard**: either non-zero -> `ValueError` naming `detector.azimuthal` and `detector.twist` (EMSphInx `:337` throws "omega tilt not yet supported"; kikuchipy's `_sample_to_detector_matrix` *does* implement both angles, so the port could support them, but the constitution defers that: v1 raises). `tilt` and `sample_tilt` are supported (they enter through `detector.sample_to_detector`, D2).
  - `signal_mask`: **kikuchipy polarity, `True` = ignore the pixel** (the `EBSD.dictionary_indexing`/`refine_orientation` convention: "only pixels equal to `False` are matched", `signals/ebsd.py:1877-1878`, `:2058-2060`; note that the *internal* `_get_direction_cosines_from_detector(signal_mask)` uses the opposite polarity, `True` = compute, `_master_pattern.py:95-96` -- the port never passes the user's mask there); shape must equal `detector.shape` (`ValueError`), boolean (`ValueError` for other dtypes, since an integer mask would silently invert the meaning). Its effect: D4 (window) and D5 (mean fill before the DCT).
  - `circular_mask=False` **by default** (open question 5.1, decided): `True` is EMSphInx' `circmask = 0` (`Geometry::maskPattern(circRad == 0)`, `idx.hpp:230`), the largest inscribed circle about the *physical* detector centre; `False` is `IndexEBSD`'s namelist default `circmask = -1` (`nml.hpp`, D9 table) and matches kikuchipy's other indexing entry points, which use no mask unless `signal_mask` is given. Measured (D8 recipe, `bw` 68, 27 rotations): without the circle the normalised argmax misorientation is median 0.344 / max 0.717 deg against 0.424 / 0.727 with it (bw 53: 0.512 / 1.040 vs 0.569 / 1.104), i.e. no accuracy is bought by discarding the corners of a rectangular detector, and the parity runs of Phase 10 against `IndexEBSD` defaults need `False`. An explicit radius (`circmask > 0` semantics) is expressed through `signal_mask` (`~_preprocessing._circular_mask(shape, r)`), never through a third parameter. **The circle is the physical circle of the unrescaled detector** (`(col - (ncols - 1)/2)^2 + (row - (nrows - 1)/2)^2 <= (min(ncols, nrows)/2)^2` in detector pixels), i.e. the circle EMSphInx' `solidAngle` applies (`interpolatePixel` on the *unrescaled* geometry, `:465-469` -> `:363-368`); EMSphInx' *LUT* loop applies it on the rescaled geometry `g = geo.rescale(wOut, hOut)` (`:511`, `dX = (X - 0.5) wOut`, `r = min(wOut, hOut)/2`), which is the same circle for square detectors and an ellipse in detector pixels for rectangular ones because `wOut` and `hOut` round independently -- so the C++ uses two slightly different circles. The port uses one (recorded deviation, documented in the class `Notes`): measured at `bw` 68 the two rules give identical windows for `(60, 60)` and `(41, 41)` and **953 (physical) vs 958 (C++) points, 5 differing, for `EBSDDetector((48, 60), pc=(0.55, 0.65, 0.6), sample_tilt=70, tilt=10)`** (`rescaled_shape (42, 52)`); the rectangular case is pinned (`n_points == 953`) so the choice is frozen, not accidental. Rationale: one predicate shared by `solid_angle_fraction` and the LUT keeps `n_points` consistent with the size arithmetic; the parity runs of Phase 10 use `circmask = -1`.
  - `oversampling` (EMSphInx `fct`, `idx.hpp:259`, `sqrt(2)`): the *linear* oversampling of the resampled detector relative to the average spherical-grid pixel, multiplied onto `scaleFactor(dim)` (D3); `> 0` (`ValueError`). Named for what it does to the sphere sampling -- for a 60x60 detector at `bw` 68 the resampled pattern is `49 x 49`, i.e. a *downsampling* of the pattern (D3 table).
- Attributes (all read-only after construction): `detector` (a `deepcopy()` of the input with `pc` unchanged -- the projector must not follow later mutations of the caller's detector), `bandwidth`, `dim`, `sht`, `signal_mask` (copy or `None`), `circular_mask`, `oversampling`, `solid_angle_fraction` (`Geometry::solidAngle(501)`, D3), `scale_factor` (`Geometry::scaleFactor(dim)`), `rescaled_shape` (`(h_out, w_out)`), `n_points` (LUT length), `sphere_index` (`(n_points,)` int64 flat index into the `(dim, dim)` **north** grid), `pixel_index` (`(n_points, 4)` int64 flat index into the rescaled `(h_out, w_out)` image), `weights` (`(n_points, 4)` float64 bilinear weights, rows sum to 1), `solid_angles` (`(n_points,)` float64, `omeg`), `window_solid_angle` (`omgW`), `sphere_solid_angle` (`omgS`), `window_fraction` (`omgW / omgS`), `window_harmonics` (`mlm`, **computed at construction**, D7 -- not lazily: the projector then holds no mutable state at all and is safe to share read-only across threads; the construction timings of D11 already include it, "mask + `mlm` 15.7 ms", and the `sht.analyze` it runs materialises the lazy `sht.quadrature_weights`, so no thread ever races on the SHT's lazy attribute).
- **Empty-window guards** (ported and extended `:424`; the C++ `Constants` uses the two-argument `rescale` overload and inherits no guard, so an empty geometry fails inside FFTW/`dctn` there): after `rescaled_shape` is computed, `h_out < 1 or w_out < 1` -> `ValueError` naming `solid_angle_fraction` and the causes ("the detector footprint covers no part of the northern hemisphere or `signal_mask` leaves nothing: solid_angle_fraction = 0.000000, the resampled pattern would be 0 x 0 pixels"); after the LUT is built, `n_points == 0` -> `ValueError` ("empty window: no Legendre grid point of dim 71 falls on the detector"). Measured: `EBSDDetector((60, 60), pc=Ni pc, sample_tilt=-40)` (and `-60`, `-80`) gives `solid_angle_fraction 0.0`, `scale_factor 0.0`, `rescaled_shape (0, 0)`, `n_points 0` -- the first guard; an all-`True` `signal_mask` likewise; a `signal_mask` that leaves only pixel `[0, 0]` gives `solid_angle_fraction 3.2e-5`, `rescaled_shape (1, 1)` and **`n_points 0`** (the 502 x 502 solid-angle grid catches the pixel, the 71 x 71 Legendre grid does not; 236 of the 400 single-pixel masks probed on a 3-px lattice behave so) -- the second guard. Both are tested (D1 tests) for a geometry cause and a mask cause.
- **Thread safety**: everything above is set once in `__init__`; `unproject` reads the LUT and writes only the `out` buffers and per-call temporaries (the `dctn` results and the kernel's `ival`), so one projector is shared by Phase 6's dask threads and only the `(north, south)` pair is allocated per chunk (`SphericalHarmonicTransform.analyze` reads only `self`, `_sht.py:941-1037` -- verified in the Phase 5 review). Sharing matters: the resident SHT tables are 5.5 / 23.1 MB at `bw` 68 / 113 (D11), so per-thread deep copies would cost 8 threads x 23 MB = 185 MB at `bw` 113 for nothing. EMSphInx' `BackProjector::clone` (shares `pLut`, allocates work) is therefore not ported.
- Methods: `unproject(pattern, *, out=None, return_image_quality=False)` (D6), `window_mask() -> (north, south)` (D4/D7), `squared_harmonics(alm) -> flm2` (D7), `image_quality(pattern) -> float` (D5), `__repr__` (`"SphericalBackProjector: bw = 68, dim = 71, detector (60, 60) -> (53, 53), window 1317 points (14.6 %)"` (the Ni detector with the default `circular_mask=False`; `(49, 49)`, `1117 points (12.4 %)` with the circle)).
- **No `flip` parameter** (open question 5.2, decided): kikuchipy patterns are always stored and displayed with row 0 at the top and `get_patterns` writes them that way (`_get_direction_cosines_for_fixed_pc` puts `gnomonic_bounds[3] = y_max` in row 0), so the LUT has exactly one row convention and nothing to flip; EMSphInx' `flip` (`Geometry::flip`, `interpolatePixel` `:360`) exists because its pattern *files* come in both storage orders (`pattern.hpp`: EDAX/EMsoft HDF5 `flip = true`, Oxford/Bruker `false`). The asymmetric-blob test of D8 pins the row direction empirically; a vertical flip, a horizontal flip and a transpose are each measured 49-85 deg away.

### D2 -- The direction -> pixel chain is the exact inverse of kikuchipy's forward projection (frozen)

- For a sample-frame unit vector `n` (a Legendre grid normal, D4): `v = M n` with `M = detector.sample_to_detector.to_matrix()` (`_sample_to_detector_matrix(sigma, theta, omega, gamma)`, `_ebsd_detector.py:100-160`: rows are the detector basis `(X_d, Y_d, Z_d)` in sample coordinates, so `M @ v_sample = v_det`; measured: `Rotation.from_matrix(M).to_matrix() == M` to `2.2e-16` and `M M^T == I` to `1.1e-16`, so `~sample_to_detector`, which `_get_direction_cosines_from_detector` uses, is the transpose); the direction is **in front of the detector** iff `v[2] > 0` (else rejected); gnomonic `x_g = v[0] / v[2]`, `y_g = v[1] / v[2]`; with `gb = detector.gnomonic_bounds.squeeze()` and the *kernel's* pixel pitch `x_scale = (gb[1] - gb[0]) / ncols`, `y_scale = (gb[3] - gb[2]) / nrows` (`_master_pattern.py:170-171`; **not** the `EBSDDetector.x_scale` property, which divides by `ncols - 1`), the continuous pixel-centre coordinates are **`col = (x_g - gb[0]) / x_scale - 0.5`, `row = (gb[3] - y_g) / y_scale - 0.5`** (row 0 is `y_max`, `_master_pattern.py:175`). Measured on the `nickel_ebsd_small` detector with `pc_average` (60x60, `binning` 8, `px_size` 1, `sample_tilt` 70, `tilt` 0): applying this chain to `_get_direction_cosines_from_detector(det)` returns the pixel centres to **`1.6e-14` (col) / `1.4e-14` (row)** pixels; asserted `<= 1e-10` (the direction cosines are normalised in float64 and the chain divides by `v[2]`, so a few `eps` per pixel unit; the constitution's "1e-12" is met with margin).
- **The sample frame is the sphere frame.** `_get_direction_cosines_from_detector` returns directions in the sample frame and `_project_single_pattern_from_master_pattern` reads the master at `rotate_vector(q, dc)` (`_master_pattern.py:511`, the active rotation `q v q*` of `kikuchipy._utils.numba.rotate_vector`), i.e. `pattern(pixel) = f_master(O n_sample)` with `O` the orix orientation (sample -> crystal). Phase 4 (D4) established `xc(zyz) = <rotate_harmonics(flm, zyz), gln>` with `rotate_harmonics(f, zyz)(n) = f((~R) n)`, `R = Rotation(zyz_to_quaternion(zyz))`; so `gln = analyze(unproject(pattern))` peaks at `~R == O`, which is exactly `_euler.rotation_from_zyz(zyz)` (`~Rotation(zyz_to_quaternion(zyz))`), **now measured, not derived** (D8): the correct sign gives 0.42 deg median over 27 rotations, the other 35 deg.
- **The frames of EMSphInx and kikuchipy coincide** (evidence, so that the C++ downstream of the pixel map applies unchanged): EMSphInx' `alpha = (90 - sTlt + dTlt)` deg puts the pattern centre at `n = (sin alpha, 0, cos alpha)` (`interpolatePixel` `:339-347`, `sampleDir` `:380-395`); kikuchipy's `Z_d` (detector normal, row 2 of `M`) at `sample_tilt` 70 / `tilt` 0 is measured `(0.34202014, 0, 0.93969262) = (sin 20 deg, 0, cos 20 deg)`; both frames have `X_d = +Y_s` (EMSphInx `x = n[1] d`, `:350`; kikuchipy `basis[0] = (0, 1, 0)`), `Y_d = +Z_s` before the tilts (`:351` at `alpha = 90`; `basis[1] = (0, 0, 1)`) and both tilts rotate about `Y_s`. Consequently `Z_s` **is the sample normal in kikuchipy's frame too**, and the C++ guard `if (signbit(n[2])) return false` (`:336`, "can't project through sample") is ported literally as **`n[2] >= 0`** on the sample-frame normal (D4).
- **Vendor conventions**: kikuchipy stores `pc` in the Bruker convention (`_ebsd_detector.py:196-201`) and the chain above reads only `pc`, `shape`, `sample_tilt`, `tilt`; **binning and `px_size` never enter** (`gnomonic_bounds` are fractions of the binned shape). Measured: `EBSDDetector(shape, pc=det.pc, binning=1, px_size=8)` gives a bitwise identical LUT to the `binning` 8 / `px_size` 1 detector; the EMsoft round trip `det.pc_emsoft() = (35.933, 137.584, 240.339)` -> `EBSDDetector(pc=..., convention="emsoft", binning=8, px_size=1)` recovers `pc` to `2.8e-17`. **Recorded discrepancy for Phases 9/10** (not this phase's code): EMSphInx' `patternCenterBruker` sets `cX = (x* - 0.5) w` (`:275-279`) while its EMsoft branch `Geometry::patternCenter` sets `cX = xpc` (`:85`; `:249` is only the comment above `patternCenterTSL`), i.e. EMSphInx equates `xpc = (x*_B - 0.5) w`, which is kikuchipy's *pre-v5* relation (`_pc_emsoft2bruker`, `version < 5: pcx = -pcx`, `:2298-2300`; v5: `xpc = (0.5 - x*_B) N b`, `:2319`). Namelists written for `IndexEBSD` must therefore use `vendor = 'Bruker'` with kikuchipy's `pc` (and `patdims`/`delta` such that `sDst = z* h pX` holds), never `vendor = 'EMsoft'` with `pc_emsoft()`; and since kikuchipy arrays are top-left origin, the pattern file must be one EMSphInx reads with `flip = true` (EDAX/EMsoft HDF5, `pattern.hpp`) or be written vertically flipped for a Bruker/Oxford `Manufacturer` (the mission's "optional vertical flip"). To be verified by the Phase 10 parity run; recorded here because the derivation lives in this chain.
- **EMSphInx' pixel-position stretch is not reproduced** (open question 5.3, decided; a deviation, documented in the class `Notes`): `interpolatePixel` maps the fractional physical position `X in [0, 1]` to `x = X (w - 1)` (`bilinearCoeff` `:528`), i.e. it treats the pixel centres `0 .. w-1` as spanning the *whole* physical width -- pixel `c` (physical centre `(c + 0.5)/w`) is sampled at `(c + 0.5)(w - 1)/w = c + 0.5 - (c + 0.5)/w`, a displacement of `+0.49` px at the left edge and `-0.49` px at the right edge (measured `0.497 / 0.489` px in the 49-px resampled image at `bw` 68). The port keeps the pixel-centre convention of `_get_direction_cosines_for_fixed_pc` (`col`, `row` above) and maps it into the resampled image with the DCT's own sampling convention (D4). Measured effect on the D8 lock with the stretch switched on: normalised median 0.488 / max 0.727 deg vs 0.424 / 0.727 without, un-normalised 0.605 / 0.710 vs 0.371 / 0.574 -- inside the coarse tolerance either way, so it cannot be told apart by an `IndexEBSD` parity run at the coarse level and is not offered as a keyword. **What the direction oracle covers and what it does not**: the oracle pins direction -> *detector* pixel `(col, row)`; a stretch applied at that stage fails it at `1e-10`. It **cannot see** a stretch applied at the resample step (`(col, row)` -> `(x, y)` in the `(h_out, w_out)` image), and neither can the D8 lock (measured: with the stretch the normalised median moves 0.424 -> 0.488 deg, all 27 still `< 2` deg) nor a single-bright-pixel argmax test (measured at `bw` 68, no circle: the argmax of a one-pixel pattern is 3.7 / 3.1 / 1.5 / 0.5 deg from `dc[r0, c0]` at `(0, 0)` / `(59, 59)` / `(59, 0)` / `(0, 59)` without the stretch but **13.6 deg at `(58, 58)` and 10.3 deg at `(50, 5)`** -- the DCT downsample of a delta rings and its maximum on the sparse window is not at the pixel -- and identical with and without the stretch at `(0, 59)`, `(30, 59)`, `(30, 0)`, `(0, 30)`, `(1, 1)`, `(10, 45)`, `(50, 5)`); the resample map is therefore pinned **structurally** in D4 (the LUT's `pixel_index`/`weights` against the formula from the reconstructed `(col, row)`, with the stretch as a measured negative control). Also recorded for the reviewer of a later "simplification": kikuchipy's `simulations/_geometrical_simulation.py:206-249` maps gnomonic coordinates to pixels with the `EBSDDetector.x_scale` property (`(x_max - x_min)/(ncols - 1)`) and no half-pixel offset -- arithmetically EMSphInx' `X (w - 1)` stretch -- and must never be substituted for this chain; `_master_pattern.py:170-175` (divides by `ncols`, offsets half a pixel) is the inverse the port implements.

### D3 -- Solid angle, scale factor and the resampled size (`:401-415`, `:465-469`, `image.hpp:143-186`)

### D4 -- The gather LUT (`Constants`, `:502-569`; `bilinearCoeff` `:526-551`)

- Iterate the **north** Legendre grid normals `_grid.legendre_normals(dim).reshape(-1, 3)` in flat order `i = y dim + x` (the C++ `xyz` order); a normal is a LUT point iff `n[2] >= 0` (physical guard, D2 -- on the north grid it rejects nothing; kept because it is the C++'s first test and it is what makes the south set empty), `v[2] > 0` (in front of the detector), `col`, `row` finite and **inside the physical extent `[-0.5, ncols - 0.5] x [-0.5, nrows - 0.5]`** (the C++ `X, Y in [0, 1]`, `:358`, closed), inside the circle when `circular_mask` (`(col - (ncols - 1)/2)^2 + (row - (nrows - 1)/2)^2 <= (min(ncols, nrows)/2)^2` -- the C++ `dX = (X - 0.5) w`, `r = min(w, h)/2` in physical pixels about the physical centre, `:363-368`, evaluated on the *unrescaled* geometry as `solidAngle` does; the C++ LUT loop's rescaled-geometry circle differs by rounding for rectangular detectors, D1 -- one predicate here), and not on a masked pixel when `signal_mask` is given (**nearest pixel**: `signal_mask[floor(row + 0.5), floor(col + 0.5)]` after clamping to the grid -- the pixel the point lies in; a bilinear-neighbour rule would shrink the window by an extra half pixel around every masked pixel for no gain, since the masked pixel's *value* is neutralised separately, D5).

- **Bilinear weights on the resampled image**: the LUT point's continuous coordinates are mapped into the `(h_out, w_out)` image with the DCT's sampling convention -- sample `k` of a length-`N` DCT-II/III sits at `(k + 0.5)/N` of the extent, so the resample of D5 preserves the physical extent and **`x = (col + 0.5) w_out / ncols - 0.5`, `y = (row + 0.5) h_out / nrows - 0.5`** (not EMSphInx' `X (w_out - 1)`, D2) -- then `i0 = clip(floor(x), 0, w_out - 1)`, `j0 = clip(floor(y), 0, h_out - 1)`, `i1 = min(i0 + 1, w_out - 1)`, `j1 = min(j0 + 1, h_out - 1)`, `wx1 = clip(x - i0, 0, 1)`, `wy1 = clip(y - j0, 0, 1)`, `wx0 = 1 - wx1`, `wy0 = 1 - wy1`; `pixel_index = [j0 w_out + i0, j0 w_out + i1, j1 w_out + i0, j1 w_out + i1]`, `weights = [wy0 wx0, wy0 wx1, wy1 wx0, wy1 wx1]` (the C++ order `:534-547`). The clamps are the C++ `min(., w - 1)` (`:528-531`) extended to the left/top rim: a point in the half-pixel rim between the edge pixel centre and the physical edge gets the edge pixel's value *along that axis* (constant extrapolation), exactly as the C++'s `X == 1` does. **The rim structure, stated in resampled coordinates (where the clamps act)**: a rim point is one with `x < 0`, `x > w_out - 1`, `y < 0` or `y > h_out - 1`; only one axis degenerates per side, so (a) every weight row sums to 1 (measured max deviation `2.2e-16`; 18 of 1117 rows are off by one ulp) with entries in `[0, 1]`, (b) for `x < 0` the two `i1`-side weights are exactly `0.0` (`wx1` clipped) and the four indices stay distinct, likewise `y < 0` and the `j1` side, (c) for `x > w_out - 1` `pixel_index[:, 0] == pixel_index[:, 1]` (`i0 = i1 = w_out - 1`) with the two weights on the pair *unequal* (`wx1 = x - i0` in `(0, 1]` is not clipped -- e.g. `col = -0.489 -> [265 266 318 319]`, `[0.083 0. 0.917 0.]`; `col = 59.34 -> [1273 1273 1322 1322]`, `[0.18 0.11 0.45 0.26]`), likewise `y > h_out - 1` and `[:, 0] == [:, 2]`; **no rim point has a weight of exactly 1** and no point outside the rim has two equal indices (measured at every `bw` -- an earlier draft asserted "two equal indices and a weight of exactly 1", which no clamp rule satisfies). ### D5 -- DCT resample, mean removal, image quality (`Rescaler::scale` `:582-618`, `imageQuality` `:489-507`)

- `_dct_rescale(pattern, h_out, w_out, *, zero_mean=True, want_iq=False) -> (rescaled, iq)`: `spectrum = scipy.fft.dctn(pattern, type=2, workers=1)` (FFTW `REDFT10`, unnormalised; the constitution's pinned convention, Phase 2 `_resize_lambert`), `iq = _image_quality_from_spectrum(spectrum)` when asked (**on the input-size spectrum, before truncation**, `:584-585`), the low-frequency corner `[:min(h_in, h_out), :min(w_in, w_out)]` copied into a zero `(h_out, w_out)` array (`:588-602`), `[0, 0] = 0` when `zero_mean` (`:604`), `rescaled = dctn(padded, type=3, workers=1)` (`REDFT01`, unnormalised; **never `idctn`**). No amplitude correction: the round trip factor is `2 h_in 2 w_in = 4 h_in w_in` (measured `14399.999999999998` for a constant `60 x 60`, and `max |dctn(dctn(x, 2), 3) / (4 h w) - x| = 1.6e-15` for a seeded standard-normal `60 x 60`; **the named convention regression of the roadmap's test box** asserts that to `1e-12` and adds the Phase 2 style negative control: `idctn(padded, type=3)` of the constant-37 spectrum padded to `53 x 53` has `ptp 189.5` where `dctn(., type=3)` gives the constant `532800 = 37 x 14400`, and its maximum is exactly `1/53^2` of the correct one -- so a `dctn`/`idctn` or `norm=` drift is caught numerically, not only by the call-recording spy), and it cancels in the unit-variance normalisation of D6 (Phase 2's `_resize_lambert` applies EMSphInx' `0.5 / new_dim^2` because *its* caller keeps amplitudes; the two helpers stay separate -- `_resize_lambert` is square-only, factor-carrying and tested; a shared helper would touch merged Phase 2 code for ten lines -- open question 5.4, decided; the docstrings cross-reference).
- **pocketfft's DCT of a constant is not exactly a delta** (new finding, ours not EMSphInx'): `dctn(np.full((60, 60), 37.0), type=2)` has AC coefficients up to `1.1e-11` (`1.0`: exactly 0; `200.0`: `4.7e-11`), so `unproject` of a constant pattern through the literal chain gives a resampled image of amplitude `~4e-11`, a weighted stdev of `5.4e-12 != 0`, and the C++'s `stdev == 0` branch is **not** taken: the sphere would receive that rounding noise normalised to unit variance. `IndexEBSD` builds its window mask through this very path (`unproject(win = ones)`, `idx.hpp:266-268`), presumably relying on FFTW's `REDFT10` being exact for a constant. The port therefore (i) builds the mask directly (D4), (ii) tests `np.ptp(pattern) == 0` **before** the DCT and takes the mask branch when true (`unproject` of `np.full((60, 60), 7.0)` and of the `uint8` constant 7 both return the window mask bitwise) with **`iq = 1.0` for a non-zero constant and `0.0` for the all-zero pattern** -- the C++ `imageQuality` of a pure DC spectrum is exactly 1 (`vIq = 0`, `:503-505`; measured on the literal transcription over `dctn(type=2)`: constants 1.0 / 7.0 / 37.0 / 200.0 give exactly `1.0` despite the AC noise, float equality `True`) and the all-zero spectrum takes the `sumP == 0` branch (`:504`, `0.0`); the short-cut is `1.0 if pattern.flat[0] != 0 else 0.0`, so the D5 identity `image_quality(p) == unproject(p, return_image_quality=True)[2]` holds for the all-zero pattern too (an earlier draft returned `1.0` unconditionally, contradicting `_dct_image_quality(zeros) == 0.0` exactly there); and (iii) keeps the literal `stdev == 0.0` branch in the kernel for a non-constant pattern whose *window* is constant -- **reachable through the real LUT only from an all-zero resampled image**: 18 of 1117 bilinear weight rows sum to `1 +- 1 ulp`, so a non-zero constant image gives a non-zero `stdev` (measured `3.5 -> 7.5e-15`, `1.0 -> 1.1e-15`, `7.0 -> 1.5e-14`, `100.0 -> 6.3e-13`, `2.0 -> 2.2e-15`, `0.0 -> exactly 0`; an exact-unit-weight variant is exact only if `window_solid_angle` is summed in the kernel's own order, which the test must not depend on) -- documented as faithful, tested by driving the kernel with the all-zero image (ones written, `0.0` returned) and, as the guard against a `stdev <= tiny` relaxation, with a seeded image of amplitude `1e-14`, which must be *normalised* (measured `stdev 6.7e-15 > 0`, weighted mean `3.8e-17`, second moment `1 - 2e-16`). Recorded in the class `Notes` and in the research-doc addendum (plan 0.9).
- **`signal_mask` pixels are mean-filled before the DCT** (open question 5.5, decided): the resample is a global spectral operation, so a dead or saturated masked pixel rings into its neighbours; measured on the D7 mask (a 12x15 block) with `Re Y_4^2` / `Re Y_8^2` patterns (scaled to `[.., ..] * 100 + 50`): with the block set to 0 the windowed correlation with the truth is 0.9812 / 0.9970, set to 255 it is 0.9323 / 0.9122, with the block replaced by the mean of the unmasked pixels 0.9965 / 0.9989 (unmasked truth 0.99999). - `_dct_image_quality(pattern) -> float` (`imageQuality`, `:489-507`; **owned by `_back_projection.py`** together with `_image_quality_from_spectrum(spectrum)`, the class method `image_quality` calls it; `_preprocessing.py` neither defines an IQ function nor binds `dctn`, so the one FFT-flag/recording test on `_back_projection.dctn` covers every `scipy.fft` call of the phase, and the preprocessing module never imports the projector module): `p = |dct2(pattern)|`, `r2[j, i] = j^2 + i^2`, `iq = 1 - sum(p r2) / (sum(r2) sum(p) / (h w))`, `0` when `sum(p) == 0`; the same `ptp == 0` short-cut as `unproject` (`1.0` non-zero constant, `0.0` all-zero) so that the two are equal by construction on constants and the literal value is asserted `abs 1e-12` there. ### D6 -- `unproject` (`:589-623`)

- `unproject(pattern, *, out=None, return_image_quality=False)`: `pattern` is any real 2-D array of shape `detector.shape` (`ValueError` otherwise), cast to float64 (a copy, so `uint8` input is safe and the input is never modified); if `signal_mask` is set the masked pixels are mean-filled (D5); if `np.ptp(pattern) == 0` the mask branch is taken without a DCT, with `iq = 1.0` for a non-zero constant and `0.0` for zeros (D5); else `_dct_rescale(..., zero_mean=True, want_iq=return_image_quality)`, then the kernel **`_unproject_kernel(rescaled_flat, pixel_index, weights, solid_angles, window_solid_angle, sphere_index, north_flat) -> stdev`** (`@njit(cache=True, nogil=True)`; no division by a possibly-zero quantity outside the guarded branch, no `error_model`): `ival[p] = sum_k rescaled[pixel_index[p, k]] weights[p, k]` (`BiPix::interpolate`, `:513-517`), `mean = sum(ival omeg) / omgW` (`:598`), `ival -= mean`, `stdev = sqrt(sum(ival^2 omeg) / omgW)` (`:601-605`), **`if stdev == 0.0: north[sphere_index] = 1; return 0.0`** (`:607-611`), else `north[sphere_index] = ival / stdev` (`:613-616`) and return `stdev`. `north` is `out[0]` (validated `(dim, dim)` float64 C-contiguous, written in place -- Phase 6 reuses one pair per thread; **only the LUT points are written**, everything else is left as is, exactly the C++ contract, so a caller passing a non-zero buffer keeps its stale values off the window -- documented; the default allocates `np.zeros`), `south` is `out[1]` untouched or a fresh zeros array. Returns `(north, south)` or `(north, south, iq)`. The C++ return value `var = sqrt(omgW/omgS 4 pi)` (`:619`) is a per-geometry constant feeding the dead `Indexer::sum2` (Phase 4 D8) and is **not** returned; `window_fraction` exposes `omgW/omgS`.
- Identities pinned (measured on a real Ni pattern): the weighted mean of `north[sphere_index]` is `-9.6e-16` and the weighted second moment `1 - 9e-16` (asserted `<= 1e-10` each, the constitution's tolerance); the resampled image's stdev is `4.9e5` (the unnormalised DCT gain), which the normalisation removes -- `unproject` does not return it, so the `stdev > 0` check is made by calling `_unproject_kernel` directly on the `_dct_rescale` output; the un-windowed grid points are exactly 0; `south` is exactly 0. `unproject` allocates its temporaries per call and never stores them on the instance (thread sharing, D1).
- Timing (measured, D11): **0.06-0.08 ms per pattern** at `bw` 53-113 including the DCT (DCT + IQ `0.06` ms, DCT alone `0.04` ms, gather kernel `0.004` ms at `bw` 68), i.e. the SHT `analyze` (0.19 / 0.40 / 0.83 / 1.83 ms at `bw` 53 / 68 / 88 / 113) dominates the per-pattern cost that Phase 6 adds to the correlator's 14-26 ms at `bw` 68.
