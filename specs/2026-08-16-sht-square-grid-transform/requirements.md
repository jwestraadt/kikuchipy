# Phase 1 -- `sht-square-grid-transform`: requirements

## Scope

In scope (all private, under `src/kikuchipy/indexing/_spherical/`):
- **Square spherical grids** (`_grid.py`), ports of `EMSphInx/include/sht/square_sht.hpp` (`namespace square`, `lambert`, `legendre`): odd side length `dim`, north/south hemispheres as `(dim, dim)` row-major arrays sharing the equator ring; ring `y` (Chebyshev distance from the centre pixel) has `N_phi(y) = max(1, 8y)` points starting at azimuth 0 and walking counter-clockwise; two layouts, `"lambert"` (Rosca equal-area; `cos theta_y = 1 - (2y/(dim-1))^2`) and `"legendre"` (ring latitudes at the non-negative roots of `P_{dim-2}` -- the zero root is the equator ring -- plus an explicit pole at `cos theta = 1`).
- **Discrete spherical harmonic transform** (`_sht.py`), port of `DiscreteSHT`: `analyze` (north, south -> `alm[m, l]`, m-major complex128, `l < m` zero) and `synthesize` (inverse), with the Sneeuw ring quadrature weights (`computeWeightsSkip`, one weight set per skipped ring for Lambert, `skip = 0` replicated for Legendre), Schaeffer's normalised associated-Legendre recursion (`amn`, `bmn`) evaluated on the fly, real ring FFTs, and the equator-symmetric/antisymmetric split.
- **FFT sizing** (`_fft.py`): `fast_size(n)`, verbatim port of `EMSphInx/include/util/fft.hpp:438-491` ({2,3,5,7,11,13}-smooth via the C++ set-product iteration; `n <= 16 -> max(1, n)`; `n < 0 -> ValueError`), and `fast_bandwidths(bandwidth_min=16, bandwidth_max=512)` (bandwidths for which `2*bw - 1` is already fast; bounds from `nml.hpp:635`). Both private in this phase; the public `kp.indexing.fast_bandwidths()` wrapper is a Phase 6 deliverable (roadmap amended accordingly).
- Tests: ports of `EMSphInx/test/sht/square_sht.cpp`, independent single-harmonic oracles for `analyze` and `synthesize`, grid/weight invariants, one real-data test on the shipped Ni master pattern.

Out of scope: Wigner-d (Phase 3), master-pattern regridding `toLegendre`/`toLambert` and DCT rescaling (Phase 2), any public API, CHANGELOG entry (no user-facing change -- the amended roadmap gate list exempts such phases), float32 path.

## Decisions

- **Layout of `alm`**: `alm[m, l]` (m-major, l-minor), complex128, shape `(bw, bw)`, `l < m` entries zero, only `m >= 0` stored; `a^l_{-m} = (-1)^m conj(a^l_m)`; fully normalised harmonics so `f == 1` gives `a^0_0 = sqrt(4 pi)`.
- **Harmonic convention (decided, to be confirmed by test, not discovered)**: EMSphInx's ALF recursion omits the Condon-Shortley `(-1)^m` and re-applies it to odd `m` when weighting the ring spectrum (`square_sht.hpp:439`) and when assembling the ring spectrum in `synthesize` (`:554-555`). The net effect, verified numerically by the reviewers with a faithful transcription, is that the stored `alm` **equals the coefficients of `scipy.special.sph_harm_y` (Condon-Shortley phase included)**: analysing `Re Y_l^m` gives `alm[m, l] = +0.5` for `m > 0` and `+1.0` for `m = 0`; analysing the complex `Y_l^m` gives `alm[m, l] = +1`. This is asserted with signed values (a dropped phase yields `-0.5`) and frozen in the `SphericalHarmonicTransform` docstring.
- **Grid conventions**: `dim` odd, `dim >= 3` (`ValueError` otherwise); `Nt = (dim+1)//2` rings; hemisphere arrays `(dim, dim)` with `X = i/(dim-1)` along axis 1 (columns) and `Y = j/(dim-1)` along axis 0 (rows), exactly EMSphInx's `j*dim + i`; the sphere is `north` then `south`. Default `dim` for a bandwidth: Legendre `bw + 2` if `bw` odd else `bw + 3`; Lambert `2*bw + 1` (`square_sht.cpp:110-111`). Bandwidth limits: Legendre `bw <= dim - 2`, Lambert `bw <= (dim-1)//2` (`square_sht.hpp:340-345`).
- **Lambert latitudes** are computed with the C++ integer recursion (`numer -= delta; delta += 8`, one rounding), not the closed form (two roundings, 1 ulp apart -- and the Sneeuw system is ill-conditioned enough for that to matter at large `dim`).
- **Legendre roots** come from `numpy.polynomial.legendre.leggauss(dim-2)` (Golub-Welsch), non-negative half sorted descending, exact `0.0` last (`dim-2` is odd); agreement with EMSphInx's bisection roots is asserted to 1e-13 against a transcription of `legendre::roots`. `legendre_roots(n)` documents that only odd `n` reproduces EMSphInx.
- **Ring weights** are always solved from the Sneeuw system (`computeWeightsSkip` port with `numpy.linalg.solve`); for the Legendre layout the unique solution *is* the Gauss-Legendre weight set with the equator weight halved (identity confirmed by the reviewers to 1e-14), so that identity is a **hard test**, not a measurement.
- **Precision guard**: `quadrature_weights` raises `ValueError` when `|sum(w_hat) - 1| > cbrt(eps)/64` (`square_sht.hpp:1057-1058`). Deliberate, recorded deviation: EMSphInx tests only the signed residual `delta > thr`; we test `|delta|` because a large negative residual is equally unusable. **Consequence (measured by the reviewers, to be re-measured and recorded):** the Lambert Chebyshev-Vandermonde system is ill-conditioned; the guard first trips near `dim ~ 277-301` and `dim = 401` fails by orders of magnitude, so **the Lambert layout is numerically usable only for `dim <~ 275`**; master patterns at 401/1001 px must be regridded to a Legendre grid before analysis (Phase 2 `toLegendre` -- which is exactly what EMSphInx does). The constitution's tech-stack line on "401-px Lambert master supports bw <= 200" is amended to say so.
- **Ring FFTs, dual path**: (a) numba path -- `analyze`/`synthesize` as single `@njit(cache=True, nogil=True)` kernels with precomputed ragged per-ring cos/sin DFT tables (avoids a Python-level per-ring loop for the per-pattern pipeline); (b) `scipy.fft.rfft`/`irfft(..., workers=1)` per ring in Python with the Legendre recursion in numba. The crossover is keyed on **grid size, not bandwidth** (`numba_ring_dft_max_dim = 131`, i.e. table size, since Lambert `dim = 2*bw + 1` and master-pattern grids would otherwise allocate 60-130 MB of tables); tables are memoised per `(dim, bandwidth)`; a class attribute lets tests force either path; both agree to 1e-12.
- **FFT normalisation**: (1) `analyze` uses an unnormalised forward real transform (FFTW `r2c`) because the `1/N_phi(y)` is already folded into `w_y = 4 pi w_hat_y / N_phi(y)`; (2) `synthesize` multiplies `irfft` output by `N_phi(y)` (or uses `norm="forward"`) because FFTW's `c2r` applies no `1/n`.
- **Legendre-layout Nyquist property** (documented in the docstring): because Legendre uses the `skip = 0` weight set for every `m`, ring `y = m/4` (which has `2m` samples, so its `rfft` bin `m` is a structurally real Nyquist bin) is not excluded for orders `m % 4 == 0`; this gives an `O(w_{m/4})` systematic error for those orders that shrinks with `dim` and is the reason EMSphInx's own Legendre round-trip tolerance is `5e-3` while Lambert reaches `1e-13`.
- **Reuse / cross-checks**: `_lambert2vector(x, y)` (inputs in `[-1, 1]`) equals `square_to_sphere((x+1)/2, (y+1)/2)`, and `sphere_to_square(v) == (_vector2lambert(v)/sqrt(pi/2) + 1)/2` (two different affine maps; asserted to 1e-12 -- `_lambert2vector` is compiled with `fastmath`); the port does not call them because it needs the `[0, 1]` parametrisation and the odd-`dim` ring structure.
- **Licence header**: kikuchipy GPL header + delimited third-party block per `specs/tech-stack.md` (CMU/Lenthe notice verbatim, GPL-2.0-or-later conveyed under GPL-3.0-or-later, "changed by Johan Westraadt, 2026-08"), enumerating the ported functions per file.
- **No public API in this phase**; nothing is added to `indexing/__init__.pyi`. Numpydoc `Examples` blocks on `fast_size` and `SphericalHarmonicTransform.analyze` so the doctest gate collects tests.
