Measured (closed form via `gammaln` + `eval_jacobi`, confirmed with `mpmath` at 50 digits): `d^511_{400,300}(2.5) = -1.209e-184` by the closed form but `0.0` by the recursion (`c2 = cos(1.25) = 0.315`: `c2 ** 610 = 1.7e-306`, `c2 ** 620 = 1.7e-311` (subnormal), `c2 ** 700 = 0.0`); on a stride-7 `(k, m)` scan at `j = 511` the largest true `|d|` zeroed is 5.3e-143 (`beta` 2.5, `(k, m) = (343, 301)`) and 1.3e-139 (`beta` 3.0, `(175, 112)`), and at `j = 127` nothing above 2.6e-276 is lost for `beta in {2.5, 3.0, 3.13, pi - 1e-3}` (nothing at all for 2.5 and 3.0). Values that small are irrelevant to every consumer (correlation, refinement), which is why X-numbers stay out of scope; the limitation is pinned by a named test and a weekly scan (`validation.md`) rather than avoided. Also out of scope: a memory-lean `rotate_harmonics` (the port allocates the full `2 bw^3` table, as EMSphInx does).

## Decisions

### Conventions (decided, confirmed by the Mathematica tables, then frozen in the docstrings)

- **Reduced Wigner d**: `d^j_{k,m}(beta) = sqrt((j+k)!(j-k)!/((j+m)!(j-m)!)) cos(beta/2)^(k+m) sin(beta/2)^(k-m) P^{(k-m, k+m)}_{j-k}(cos beta)` (Fukushima 2016 eq. 1, `wigner.hpp:48`), i.e. Mathematica `WignerD[{j, k, m}, beta]` (`:74`). `j` is the degree, `k` the first order and `m` the second order (Fukushima's letters, kept throughout `_wigner.py`; the SHT modules keep `l`/`m`). **This is the transpose of the Wikipedia/Varshalovich small-d**: `d^{EMSphInx}_{k,m}(beta) = d^{Wiki}_{m,k}(beta) = d^{Wiki}_{k,m}(-beta)`; checked against `tab12`: `d^1_{1,0}(pi/2) = +1/sqrt(2)`, `d^1_{0,1}(pi/2) = -1/sqrt(2)`, `d^2_{2,1}(pi/3) = +0.6495190528`, whereas Wikipedia's `d^1_{1,0} = -sin(beta)/sqrt(2)`. Independent confirmation: the closed form above evaluated with `scipy.special.eval_jacobi` reproduces the table (`d^1_{1,0}(pi/2) = 0.7071067811865477`, `d^2_{2,1}(pi/3) = 0.649519052838329`). sympy is not used (constitution) and its small-d convention differs by that transpose (`critique-plan-faithful-port.md` m6).
- **Wigner D and rotation of coefficients**: `D^j_{k,m}(alpha, beta, gamma) = d^j_{k,m}(beta) exp(i (m alpha + k gamma))` = Mathematica `WignerD[{j,k,m}, gamma, beta, alpha]` (`:100-101`, `:436-439`); `b^l_m = sum_{n=-l}^{l} a^l_n D^l_{m,n}(zyz)` (`:153`, `:768`). Note the variable naming in `rotateHarmonics`: `expAlpha` carries `exp(i m gamma)` (`:780`) and `expGamma` carries `exp(i n alpha)` (`:782`) -- the mathematics matches `D` above; the port names them by content (`exp_m_gamma`, `exp_n_alpha`). Only `n >= 0` is stored; the `-n` term uses `a^l_{-n} = (-1)^n conj(a^l_n)` (Phase 1 convention) and `d^l_{m,-n}(beta) = (-1)^(l+m) d^l_{m,n}(pi - beta)`, which is why slot 1 of the table is multiplied by `(-1)^(l+m+n)` (`:794`).
- **Direction of `rotate_harmonics` (determined by probe, to be asserted, then frozen)**: with `R = Rotation(zyz_to_quaternion(zyz))` (orix), `A = R.to_matrix().T = Rz(alpha) Ry(beta) Rz(gamma)` (the active ZYZ matrix; `R.to_matrix()` is the passive one, `(Rz Ry Rz)^T`), and `g = synthesize(rotate_harmonics(analyze(f), zyz))`: **`g(n) = f(A n) = f((~R) * n)`**, equivalently **`g(R * n) = f(n)`** -- the features of `f` are moved by orix' active vector rotation `R * v`. Measured with a faithful transcription of `rotateHarmonics` at `bw` 16 on a band-limited `f` (`bw` 8): `max |g(n) - f((~R) * n)| = 1.9e-14` and `max |g(n) - f(R.to_matrix() @ n)| = 8.1` (the wrong direction). Special case `beta = 0`: `b^l_m = a^l_m exp(i m (alpha + gamma))`, i.e. `g(n) = f(Rz(alpha + gamma) n)` (measured 8.7e-15). **The direction is pinned twice**: by the `sph_harm_y` oracle (scipy >= 1.15, `importorskip`) *and* by a dependency-free brute-force sum `rotate_harmonics(alm, zyz)[m, l] == sum_{n=-l}^{l} a^l_n wigner_D(l, m, n, zyz)` with `a^l_{-n} = (-1)^n conj(a^l_n)` (measured 9.0e-16 at `bw` 8, 5.7e-16 at `bw` 6, for `beta` positive, negative and `pi`; the transposed read `wigner_D(l, n, m, zyz)` differs by 0.45-2.7). The second form runs on the CI "oldest" job, where the scipy oracle skips, and matters because the transposed-`dBeta[n, m, j]` read of the rotation kernel is exactly conjugation by the 2-fold about z (`d^j_{n,m} = (-1)^(m-n) d^j_{m,n}`, an inner automorphism), which every group-theoretic identity below (identity, inverse, composition, power, glide) and the Ni real-data check survive; only an oracle that fixes `D` itself kills it (`wigner_D` is pinned to Mathematica at `2 eps`). What this means for orientations (crystal->sample vs sample->crystal) is **not** decided here; Phase 5's forward-projection test decides it (see `rotation_from_zyz` below).
- **Composition order (determined, then frozen)**: `rotate_harmonics(rotate_harmonics(alm, z1), z2) == rotate_harmonics(alm, quaternion_to_zyz((Q2 * Q1).data))` with `Q = Rotation(zyz_to_quaternion(z))` and orix' Hamilton product -- **later rotation on the left** (measured 2.0e-15; the other order differs by 2.4). orix' `Quaternion.__mul__` equals EMSphInx `quat::mul` (`quaternion.hpp:417-427`) with `pijk = +1` (`constants.hpp:66`) to 1.4e-17, so `Q2 * Q1` is also what `xtal::Quat::operator*` computes.
- **Inverse**: `rotate_harmonics(rotate_harmonics(alm, (a, b, g)), (-g, -b, -a)) == alm` (measured 7.9e-16) and `quaternion_to_zyz(~Q)` does the same (4.3e-15).

### Recursion and numerics

- **Fukushima's three-term recursion in degree** exactly as `wigner.hpp:204-286` (`u_jkm_{0,1,2}`, `v_jkm`, `w_jkm`, `a_jkm_{0,1,2}`, `b_jkm`, `u_km_{0,1,2}`, `a_km_{0,1,2}`, `e_km`), with the branch on the sign of `t = cos(beta)`: type 0 for `t > 0` (uses `tc = 1 - t`), type 1 for `t == 0` (`u = -k m`), type 2 for `t < 0`; the tables group type 1 with type 0 (`isType0 = !signbit(t)`, `:467`), which is bitwise identical because `u_km_0(k, m, tc=1) = -m = u_km_1` and `u_jkm_0(j, k, m, 1) = -k m = u_jkm_1` exactly in floating point.
- **Integer arithmetic in int64**: `(j+k)(j-k)(j+m)(j-m) <= 512^4 = 6.9e10 > 2^31` -- 32-bit ints overflow at `k ~ 215` (`:227`), int64 is good to `~55 000`. Every njit kernel takes Python ints (numba int64) and casts to float only inside the `sqrt`, as the C++ `Real(...)` does.
- **Shared coefficient helpers and operation order**: the scalar `wigner_d`, `wigner_d_half_pi` and every table kernel call the *same* `@njit` helpers (`_e_km`, `_w_jkm`, `_v_jkm`, `_b_jkm`, `_a_jkm_0/1/2`, `_a_km_0/1/2`, ...) with the C++ association preserved (e.g. `b_jkm = w * (sqrt(...) * j)`, not `(w * sqrt(...)) * j`; powers `c2 ** float(n)`, never repeated multiplication). Consequence, and a hard test as in `wigner.cpp:424-425`: **the tables are bitwise equal to the scalar function** on every defined slot (`==`, no tolerance). The drafting probe's faithful transcription achieves this in pure Python and in a numba kernel; a probe with one re-associated product (`(w * sqrt) * i`) broke it at 1.7e-16 -- so the shared helpers are a requirement, not a style choice.
- **Symmetry reduction** (`:300-315`) is written iteratively (sign accumulation, `k`/`m` swap, `t -> -t`), not recursively (numba's self-recursion support is fragile), followed by a non-recursive core for `0 <= m <= k <= j`; the six identities (eqs. 5-9 and `j < max(|k|, |m|) -> NaN`) are asserted individually.
- **Undefined slots are NaN, not garbage** (deliberate, recorded deviation from `:108` and `:124`; the `pi/2` table of `:699-761` leaves the same slots unwritten): every table is allocated with `np.full(..., nan)` and the kernels write only the defined slots `j >= max(k, m)`; a stray read then poisons the result loudly instead of silently. `wigner_d_table_pre(..., out=table)` re-uses a caller-owned buffer without re-filling (Phase 7 calls it once per Newton iteration; the never-written slots keep their NaN from the first allocation), so the fill costs nothing on the hot path. **The NaN invariant on the `out=` path is caller-owned but guarded**: `wigner_d_table_pre` checks shape `(bw, bw, bw, 2)`, dtype float64, C-contiguity *and* that the two representative undefined slots `out[bw-1, 0, 0, 0]` and `out[0, bw-1, 0, 1]` (undefined for every `bw >= 2`; `bw == 1` has no undefined slot) are NaN, raising `ValueError` otherwise -- so `out=np.empty(...)` is rejected instead of silently returning garbage in the ~5/6 of slots the kernel never writes, while a buffer from a previous call or from `np.full(nan)` passes at O(1) cost; the docstring states that all undefined slots must already be NaN (the check is a tripwire, not a full scan). Cost of the fill at allocation: `np.full((bw, bw, bw, 2), nan)` measured 0.90 / 1.96 / 4.08 / 11.9 ms at `bw` 68 / 88 / 113 / 158, i.e. **~0.65x the recursion time** (1.39 / 2.94 / 6.40 / 17.9 ms) -- not negligible, and *excluded* from the numba baselines below, which time a kernel writing into a pre-allocated array; `validation.md` therefore times `wigner_d_table` including its allocation and `wigner_d_table_pre(out=...)` without it.
- **`wigner_d_prime`/`wigner_d_prime2` return NaN for `j < max(|k|, |m|)` by an explicit guard, and `wigner_d_prime2` evaluates `d2Coef` only inside its `k + 1 < j` branch.** Two recorded deviations with identical results, both forced by `math.sqrt`: numba's returns NaN for a negative argument, Python's raises `ValueError: math domain error`, so anything the C++ leaves to `sqrt` of a negative product makes the compiled kernel and its `.py_func` disagree. (i) For `|k| > j` the C++ gets NaN from `sqrt((j-k)(j+k+1))` (`:820`, `:842`), for `|m| > j >= |k|` from `d()` itself -- the explicit guard covers both. (ii) `dPrime2` computes `d2Coef = rjk * sqrt((j-k-1)(j+k+2))` unconditionally at `:845`, and that radicand is negative for **every defined slot with `k == j`** (`(j-k-1)(j+k+2) = -(j+k+2)`: -2, -4, -6, -8 for `(j,k,m) = (0,0,0), (1,1,0), (2,2,1), (3,3,3)`); the C++ never uses it there (the ternary at `:850`, `k+1 >= j ? 0 : ...`), the compiled kernel would carry a harmless NaN, but the `.py_func` raises on the very first entry of the ported `testDerivatives` (`j = k = m = 0`) and on every first degree of the Phase 7 pinning loop. The port therefore writes `d2_term = 0.0 if k + 1 >= j else wigner_d(j, k+2, m, t, nB) * (rjk * sqrt((j-k-1)(j+k+2)))` (association as `:845`/`:851`), which is bitwise the C++ value wherever the C++ value is defined; measured with the guarded transcription: `wigner_d_prime2` at `(0,0,0), (1,1,0), (2,2,1), (3,3,3)` with `t = 0.5` gives `0.0, -0.6123724356957947, -1.299038105676658, 0.421875`, all inside the `24 eps` table test. Named tests assert these four are finite for the dispatcher *and* the `.py_func`.
- **Beta wrapping** (deliberate, recorded deviation): `rotate_harmonics` and `wigner_D` first wrap `beta` into `[-pi, pi]` with `wrap_beta` (`fmod(beta, 2 pi)`, then `+-2 pi`; identical to `sht_xcorr.hpp:895-899`). `rotateHarmonics` (`:776`) and `D` (`:438`) do not, and are wrong outside `[-pi, pi]` because `signbit(beta)` no longer identifies the branch: measured `rotateHarmonics(alm, (a, 4.0, g)) != rotateHarmonics(alm, (a, 4.0 - 2 pi, g))` by 2.2 although they are the same rotation. Inside `[-pi, pi]` the port is identical to the C++. `wigner_d_table` and the scalar functions take `(cos_beta, negative_beta)` as the C++ does and cannot wrap; their callers must (asserted by a test on `rotate_harmonics`).
- **Table layouts** (frozen; the correlator of Phase 4 and the derivatives of Phase 7 index them exactly like the C++):
  - `wigner_d_table` / `wigner_d_table_pre` -> `float64 (bw, bw, bw, 2)`, C-contiguous, `table[k, m, j, 0] = d^j_{k,m}(beta)`, `table[k, m, j, 1] = d^j_{k,m}(pi - beta)`, i.e. the C++ flat index `(k bw^2 + m bw + j) 2 + s`. Both slots are computed by the simultaneous `+t`/`-t` recursions of `:518-546`. Negative orders are recovered with `d^j_{-k,-m}(b) = (-1)^(k-m) d^j_{k,m}(b)`, `d^j_{k,-m}(b) = (-1)^(j+k) d^j_{k,m}(pi-b)`, `d^j_{-k,m}(b) = (-1)^(j+m) d^j_{k,m}(pi-b)` (`:111-114`). `negative_beta=True` swaps the `(k, m)` and `(m, k)` signs (`:499`), i.e. `table[k, m, j, s](nB) == table[m, k, j, s](not nB)`.
  - `wigner_d_table_factors(bw)` -> `e_km (bw, bw)` with `e_km[k, m]` for `m <= k`; `w_jkm (bw, bw, bw)` and `b_jkm (bw, bw, bw)` with `[k, m, i]` for `m <= k`, `i >= k + 2` (`:681-689`; NaN elsewhere). Not memoised (Phase 4 stores them in its correlator constants, as `sht_xcorr.hpp:360-370` does).
  - `wigner_d_half_pi_table(bw, transpose)` -> `float64 (bw, bw, bw)`: `transpose=False`: `table[k, m, j] = d^j_{k,m}(pi/2)`; **`transpose=True`: `table[m, k, j] = d^j_{k,m}(pi/2)`** (`:144-145`), which is what the correlator allocates (`sht_xcorr.hpp:368`, reads at `:736-756`). No default: callers state which one they want. The two are exact transposes of each other (`transposed == untransposed.transpose(1, 0, 2)`) and `table[k, m, j] = (-1)^(k-m) table[m, k, j]`.
- **Memory** (recorded, no guard): `2 bw^3` doubles for the beta tables and the pre-factors, `bw^3` for the `pi/2` table: `bw` 68 -> 5.0 / 5.0 / 2.5 MB; 88 -> 10.9 / 10.9 / 5.5 MB; 113 -> 23.1 / 23.1 / 11.5 MB; 158 -> 63 / 63 / 32 MB; 384 -> 906 MB per beta table (so `rotate_harmonics` at master-pattern bandwidths is a test/visualisation tool, never a per-pattern operation; documented in the docstring). **Additive peaks** (recorded, since the pieces are held simultaneously): a `wigner_d_table_pre` caller holds `w_jkm + b_jkm + table = 4 bw^3` doubles -> 10.1 MB (`bw` 68), 21.8 (88), 46.2 (113), 126 (158), 1.81 GB (384); the Phase 4 correlator additionally holds the transposed `pi/2` table (`sht_xcorr.hpp:362-369`: `wigD` `bw^3`, `wigE` `bw^2`, `wigW`, `wigB` `bw^3` each, plus the per-call beta table) -> `5 bw^3` = 12.6 / 27.3 / 57.7 MB per thread at `bw` 68 / 88 / 113, which is the per-thread quantity `specs/tech-stack.md` requires Phase 6 to measure. Numba baselines from the drafting probe (this machine, informational; kernel time into a pre-allocated array, i.e. **excluding** the NaN fill measured above): `wigner_d_table` 1.4 ms (`bw` 68), 2.9 ms (88), 6.4 ms (113), 17.9 ms (158); the `rotate_harmonics` loop 0.35 ms (68), 0.72 ms (88) on top of the table.
- **`rotate_harmonics(alm, zyz)`** takes `alm` `(bw, bw)` complex128 (`alm[m, l]`, Phase 1 layout == `alm[n bw + j]` of `:150`), returns a new `(bw, bw)` array (the C++ uses a temporary so that `alm` may alias `blm`; we simply never write into the input), reads only `l >= m` (entries below the diagonal are ignored, the output has them zero), and validates shape/dtype (`ValueError`). `zyz` is any `(3,)` array-like in radians.
- **Derivatives -- implement now, and pin Phase 7's formulas**: `wigner_d_prime`/`wigner_d_prime2` are cheap scalar ports and get the full C++ test (`testDerivatives`, 24 eps) plus finite differences, so Phase 7 inherits a tested oracle. Phase 7's kernel will *not* call them; it inlines the table-based formulas of `sht_xcorr.hpp:1009-1041` (`d1P = d0P coef1_0PP - d0P_1 rjm` at `:1038`, `d1N = d0N coef1_0PN + d0N_1 rjm` at `:1039`, `d2P` at `:1040`, `d2N` at `:1041`, with `d0P_1 = 0` if `m >= j` and `d0P_2 = 0` if `m + 1 >= j`). Those formulas are transcribed **in the Phase 3 test module only** and pinned against the scalar ports: `d1P == wigner_d_prime(j, m, n)`, `d1N == (-1)^(j+m) wigner_d_prime(j, m, -n)`, `d2P == wigner_d_prime2(j, m, n)`, `d2N == (-1)^(j+m) wigner_d_prime2(j, m, -n)` for both signs of beta (measured at `bw` 15, the asserted bandwidth: worst 8.9e-16 / 3.1e-15 / 2.8e-14 / 5.7e-14 for `d1P` / `d1N` / `d2P` / `d2N` over `beta in {+-0.9708, +-2.5}`; asserted `abs 1e-12`, a 17x margin). No table-based derivative helper ships in `_wigner.py` (its signature belongs to Phase 7's kernel design).

### Euler angles

- **`zyz_to_quaternion` is the single source of truth for ZYZ -> orientation** (constitution). Faithful port of `zyz2qu` (`:973-989`): `sigma = (gamma + alpha)/2`, `delta = (gamma - alpha)/2`, `q = [c cos sigma, -s sin delta, -s cos delta, -c sin sigma]` (`pijk = +1`), negate if `signbit(w)` (so `-0.0` flips too), no normalisation, and if `|w| <= sqrt(eps)` (`Constants::rEps`, `xtal/constants.hpp:95`) set `w = 0` and canonicalise the axis with `orientAxis` (`:247-260`: `+z` hemisphere, `+y` half of the equator, `+x` when `y = z = 0`). Output `(..., 4)` float64 `(w, x, y, z)` == orix `(a, b, c, d)`.
- **`quaternion_to_zyz`**: faithful port of `qu2zyz` (`:996-1022`) with `thr = 10 eps` (`xtal/constants.hpp:96`): `chi = sqrt((w^2 + z^2)(x^2 + y^2))`; if `chi <= thr`: `beta = 0` and `alpha = atan2(-2 w z, w^2 - z^2)` when `x^2 + y^2 <= thr`, else `beta = pi` and `alpha = atan2(-2 x y, y^2 - x^2)`; `gamma = 0` in both; general branch `alpha = atan2(y z + x w, -y w + x z)`, `beta = atan2(2 chi, (w^2 + z^2) - (x^2 + y^2))`, `gamma = atan2(y z - x w, -y w - x z)`; negatives get `+2 pi`, so the ranges are `[0, 2 pi) x [0, pi] x [0, 2 pi)`. Consequences pinned by tests: `beta = 0` returns `((alpha + gamma) % (2 pi), 0.0, 0.0)`, `beta = pi` returns `((alpha - gamma) % (2 pi), pi, 0.0)` -- **Python modulo into `[0, 2 pi)`**, which is what the `+2 pi` wrap of `:1019` produces, *not* C/`math.fmod` (sign of the dividend: `fmod(1 - 2, 2 pi) = -1.0` where `qu2zyz` returns `5.283185307179586`); the first component agrees to `abs 1e-14` (measured worst 8.9e-16 over 2000 random pairs on each branch: `atan2(sin x, cos x)` does not round-trip `x` exactly, 978/2000 resp. 479/2000 pairs differ in the last bit), `beta` and `gamma` are exact (`== 0.0`, `== pi`) -- consistent with `D`, whose `beta = 0`/`pi` values depend on `alpha + gamma`/`alpha - gamma` only. Not `orix.Rotation.to_euler` (its degeneracy threshold is `1e-9`, not `10 eps`).
- **ZYZ <-> Bunge (the correct relation, evidence)**: `zyz_to_bunge((a, b, g)) = (a + pi/2, b, g - pi/2)`, `bunge_to_zyz((phi1, Phi, phi2)) = (phi1 - pi/2, Phi, phi2 + pi/2)`, pure affine, no wrapping. Evidence: (i) EMSphInx' own test `test/xtal/rotations.cpp:296-310` builds `zyz = (phi1 - pi/2, Phi, phi2 + pi/2)` and asserts `zyz2qu(zyz) == eu2qu(eu)` to `10 eps`; (ii) probe: `zyz_to_quaternion(zyz) == orix.Rotation.from_euler((a + pi/2, b, g - pi/2)).data` to **8.6e-16** on 1000 random triples, whereas `(a - pi/2, b, g + pi/2)` differs by 2.0 (its `x`, `y` components are sign-flipped: a 180 deg rotation about z, `critique-plan-faithful-port.md` B1, `critique-plan-kikuchipy-native.md` B1); (iii) `orix.Rotation.from_euler(eu).data` is **bitwise** `eu2qu(eu)` (`rotations.hpp:410-429`) on the same triples (`explore-emsphinx-xtal-util-vs-orix.md` 1.2 confirmed). **EMSphInx' `zyz2eu`/`eu2zyz` (`:1025-1039`) and the `@note`s at `:122`, `:129`, `:971`, `:995` have the offsets reversed** and are inconsistent with `zyz2qu`; EMSphInx never uses them on the indexing path (`indexer.hpp:242-249`, `:264-268` and `programs/master_xcorr.cpp:145,185,353` call `zyz2qu`/`qu2zyz` directly). They are not ported; the docstring of `zyz_to_bunge` records the upstream inconsistency. `sht_xcorr.hpp:594-649` (`extractBunge`) uses the reversed relation for its Bunge cube -- an open item for the phase that ports it (4 or 9), listed below.
- **`rotation_from_zyz(zyz) -> Rotation`** returns **`~Rotation(zyz_to_quaternion(zyz))`**, the conjugation of `indexer.hpp:264-268` ("crystal->sample to sample->crystal"; `quNp` is the identity: `include/modality/ebsd/detector.hpp:454-459` computes the tilt angle and then returns `{1, 0, 0, 0}` because the tilt-dependent quaternion at `:457` is **commented out upstream**, and the abstract default `include/idx/base.hpp:133` is the identity too -- an EMSphInx version that re-enables `:457` would insert a detector-tilt rotation into this chain and invalidate the `~Rotation`-only form), for `zyz` of shape `(..., 3)` (result shape `(...)`, orix semantics: `(3,)` -> shape `(1,)`). **The sign of this conjugation is provisional**: it is the faithful chain, consistent with the `rotate_harmonics` direction above (`g(n) = f(A n)`, `A = R.to_matrix().T = (~R).to_matrix()`), and Phase 5's forward-projection test through `EBSDMasterPattern.get_patterns` pins it; if Phase 5 flips it, the flip happens in this one function and its docstring. Phase 3 pins only the identities: `rotation_from_zyz(zyz).data == (~Rotation(zyz_to_quaternion(zyz))).data` exactly, `== (~Rotation.from_euler(zyz_to_bunge(zyz))).data` to 1e-14, and the round trip with `rotation_to_zyz(rotation) = quaternion_to_zyz((~rotation).data)`.
- **`wrap_beta(beta)`** lives in `_euler.py` (angle utility): `beta = fmod(beta, 2 pi); if beta > pi: beta -= 2 pi elif beta < -pi: beta += 2 pi` (`sht_xcorr.hpp:895-899`); `-0.0` is preserved (`fmod(-0.0, x) = -0.0`), which is harmless because the `nB` swap is a no-op at `beta = 0`.
- Batch shapes: `zyz_to_quaternion` accepts `(..., 3)` and returns `(..., 4)`; `quaternion_to_zyz` accepts `(..., 4)`; kernels are per-row `@njit(cache=True, nogil=True)` functions plus a 2-D batch kernel and thin Python wrappers (`ValueError` on a wrong last dimension), like orix' `_conversions`.
