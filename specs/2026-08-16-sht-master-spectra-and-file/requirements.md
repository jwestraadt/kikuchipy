Only `MasterPatternHarmonics` is added to `src/kikuchipy/indexing/__init__.pyi` (sorted `__all__`). All keyword arguments after the first are keyword-only. Names follow kikuchipy (`sample_tilt` as on `EBSDDetector`, `beam_energy` as in `metadata.Acquisition_instrument.SEM`, `original_metadata` as on every signal), not EMSphInx (`sig`, `kv`). `hemisphere` accepts exactly the three values of the ebsdsim plugin's `HEMISPHERE` literal (`"upper"`, `"lower"`, `"both"`; `"lower"` returns the south hemisphere alone) and raises `ValueError` listing them otherwise (`ebsdsim_master_pattern/_api.py:105-111`).

### D2 -- Coefficient container

`alm` is stored as a C-contiguous `(bw, bw)` complex128 copy in Phase 1's layout (`alm[m, l]`, m-major, `l < m` zero, `a_00 = sqrt(4 pi)` for `f == 1`, `scipy.special.sph_harm_y` convention incl. Condon-Shortley). The constructor raises `ValueError` if `alm` is not square 2-D or if any `l < m` entry is non-zero (`np.tril(alm, -1)` must be exactly zero) -- the `.sht` packer relies on that padding being zero (`sht_file.in.hpp:1781`). `bandwidth >= 1`.

### D3 -- `from_master_pattern` is a line-by-line port of `mp2sht` (`MasterPattern::read` + `MasterSpectra`)

Preconditions: the input is an `EBSDMasterPattern` (`TypeError` for anything else, incl. `ECPMasterPattern`); `projection == "lambert"`, otherwise `NotImplementedError` with the wording of `_is_suitable_for_projection` (`ebsd_master_pattern.py:356-359`, "Master pattern must be in the square Lambert projection") extended by "; use `as_lambert()`" -- the same exception type kikuchipy raises for that condition (`get_patterns`); not delegated to `_is_suitable_for_projection(raise_if_not=True)` because that helper also refuses `phase.point_group is None`, which D9 accepts as `(1, False)`; `hemisphere in {"both", "upper"}` (`ValueError` otherwise) -- with `"upper"` allowed only when `phase.point_group.contains_inversion`, in which case the lower hemisphere is `upper[::-1, ::-1]` (EMSphInx `makeInvSym`, `master.hpp:521-527`: `sh[(dim-1-j)*dim + (dim-1-i)] = nh[j*dim + i]`; physically `f(x, y, -z) = f(-x, -y, z)` and both hemispheres are stored at the square coordinates of `(x, y, |z|)`, `square_sht.hpp:592-606` and kikuchipy `_master_pattern.py:554-556`); `"lower"` alone raises `ValueError`. Lazy signals are computed (`np.asarray(data)`); data is cast to float64 after the atom sum, which kikuchipy's EMsoft reader has already done (`_emsoft_master_pattern.py:167-174`, `data.sum(axis=sum_axis).astype(data.dtype)`). **Recorded, scoped**: that reader sums the atom sites in the *file* dtype whereas EMSphInx reads `mLPNH` as `NATIVE_FLOAT` and accumulates in float32 (`master.hpp:330-338`), so the two agree only for `numset == 1` (the in-package Ni master: `EMData/EBSDmaster/numset == [1]`, `mLPNH (1, 1, 401, 401) uint8`) or float sources (`master_patterns.h5`: `Natomtypes 2` but float32); for an integer multi-site master (`combinesites = .FALSE.` in EMsoft, `numset > 1`) the uint8/uint16 sum wraps modulo the dtype and the mp2sht parity claim is void. `from_master_pattern` therefore raises `ValueError` naming `combinesites` when the signal dtype is integer (`dtype.kind in "iu"`), `original_metadata.CrystalData.Natomtypes > 1` and `original_metadata.EBSDMasterNameList.combinesites` is missing or false (the in-package file carries `combinesites 0`, `Natomtypes 1`); a synthetic 2-site uint8 master (both keys set) is in the test list. Signals without those keys pass.

Pipeline, in this order (`dim` = source Lambert side, `bw` = requested bandwidth):

1. Energy weighting (D4): `north = sum_e w_e * data[0, e]`, `south = sum_e w_e * data[1, e]` in float64 (`master.hpp:340-348`).
2. `dim_leg = default_dim(bw, "legendre")` (`bw + 2` if odd else `bw + 3`; `master.hpp:551`).
3. `dim_scaled = round(sqrt(2) * dim_leg)` and DCT rescale of both hemispheres from `dim` to `dim_scaled` (D5; `master.hpp:387-388`), also when `dim_scaled < dim` (crop branch, e.g. the 1001 px master -> 547) and skipped when `dim_scaled == dim` (`:356`).
4. Bilinear sampling at the Legendre normals (D6; `master.hpp:390-408`) -> `(dim_leg, dim_leg)` north and south.
5. If `normalize`: solid-angle weighted mean and standard deviation (D7; `master.hpp:557-584`).
6. `SphericalHarmonicTransform(bw, "legendre", dim_leg).analyze(north, south)` (`master.hpp:593`). No DC removal (`:594` is commented out in EMSphInx; `remove_dc()` is explicit).
7. `beam_energy` and `sample_tilt`: the keyword if given, else `original_metadata.MCCLNameList.EkeV` / `.sig` (what `MasterPattern::read:249-250` reads; note EkeV is 20.1 for the in-package Ni master while its energy axis says 20.0), else `ValueError` naming the keyword. `original_metadata` (the class attribute) is assembled per D11 from the signal's `original_metadata` (`MCCLNameList`, `BetheList`, `EBSDMasterNameList`, `CrystalData`) so that `save()` writes the same crystal and simulation blocks as `mp2sht`; its `header.notes` records the provenance `f"created with kikuchipy (normalize={normalize}, emsphinx_compatible={emsphinx_compatible})"` (mp2sht writes `"created with mp2sht"`), which `save(notes=None)` writes to the file so that a `.sht` with `a_00 ~ 0` (opt-in `emsphinx_compatible=False`, D7) is recognisable from its header.

Reference measurement (scratch NumPy transcription of the above on top of Phase 1, 2026-08-16, this machine): against the `mp2sht.exe` output on the same input, rel-L2 over all coefficients **2.2e-9** (uint8 401 px Ni master, 1 energy) and **8.6e-10** (float32 1001 px Ni master, 16 energies); after `remove_dc` on both, 5.1e-9 and 3.1e-9; `a_00` agrees to 7e-12 absolute; relative power in the slots the packer discards 6.4e-30 / 4.4e-30; worst single coefficient difference 1.1e-9 at `(m, l) = (0, 152)`. So the parity gate below is asserted at **rel-L2 < 1e-6** (measured-then-pinned with > 100x margin for other BLAS/FFT builds; the outer bound of the roadmap, 1e-3, would let a wrong weight set through), not discovered.

### D4 -- Energy weights (`accum_e`)

`energy_weights`:
- `None` and the signal has one energy (no `"energy"` navigation axis): `[1.0]`.
- `None` and the signal has an `"energy"` axis: read `EMData/MCOpenCL/accum_e` from the source HDF5 file located through `tmp_parameters` (`folder`, `filename`, `extension`, set by `kp.load`, `io/_io.py:140-142`); `ValueError` if the file or the dataset is missing, naming `energy_weights`. The dataset is summed over every axis but the **last** (h5py C-order shape `(ny, nx, nE)`, e.g. `(501, 501, 16)` in the cached Ni master and `(201, 201, 1)` in the in-package one; `master.hpp:274-275` sums `slicePts = dims[0]*dims[1]` slices of length `dims[2]`) in int64, then each energy of the signal axis is mapped to bin `k = round((E - Ehistmin)/Ebinsize)` (`original_metadata.MCCLNameList`; `EkeVs[k] = Ehistmin + k*Ebinsize`, verified on both Ni files), `ValueError` if a bin is out of range; the selected counts are normalised to sum 1 (`master.hpp:276-278`). With every bin loaded this equals EMSphInx exactly (Ni full master: `[0, 0, 1455, 266084, 5365299, 18896238, ..., 191778041, 334039769, 161050771] / 1151726624`); with a subset (`kp.load(..., energy=(15, 20))`) EMSphInx would refuse (`:319`, bin-count mismatch) and we renormalise over the loaded bins -- documented deviation.
- An array-like of length `n_energies`: cast to float64, `ValueError` if any weight is negative or the sum is zero, normalised to sum 1.

`kikuchipy.data.nickel_ebsd_master_pattern_small` has one energy bin (`accum_e` shape `(201, 201, 1)`), so the in-package path is a no-op; the multi-energy path is unit-tested on synthetic `accum_e` arrays and on the in-package `master_patterns.h5` (11 energies, **no** `accum_e` -> `ValueError` unless `energy_weights` is passed) and end-to-end weekly on the cached full master.

### D5 -- DCT rescale (`MasterPattern::resize`, `image::Rescaler::scale`)

`_resize_lambert(image, new_dim)`: `X = scipy.fft.dctn(image, type=2, workers=1)` (== FFTW `REDFT10`, unnormalised), truncate/zero-pad `X` to `(new_dim, new_dim)` keeping the low-frequency corner (`image.hpp:588-602`), `out = scipy.fft.dctn(X_padded, type=3, workers=1)` (== FFTW `REDFT01`, unnormalised; **never** `idctn`, `specs/tech-stack.md`), then `out *= 0.5 / new_dim**2` (`master.hpp:365-367`). Recorded fact: that factor is amplitude preserving only when `new_dim**2 == 2*dim**2` (the unnormalised pair scales a constant by `4*dim**2 * 0.5/new_dim**2 = 2*dim**2/new_dim**2`, i.e. 1.075 for 401 -> 547 and 6.7 for 1001 -> 547); it cancels in the normalisation of D7 and is ported verbatim, not "fixed" (`normalize=False` therefore reproduces EMSphInx's amplitude, not the source's). Test oracle: a constant image `c` rescales to `c * 2*dim**2/new_dim**2` everywhere (rel 1e-12), for both the pad (13 -> 21, 401 -> 547) and crop (21 -> 13, 1001 -> 547) branches; a low-order DCT mode `cos(pi*k*(n+1/2)/dim)` upsamples to the same mode on the new grid.

### D6 -- `toLegendre` bilinear sampling (`master.hpp:390-408`, `image.hpp:513-553`)

For every Legendre normal `v` of `legendre_normals(dim_leg)` (Phase 1, north hemisphere), `(X, Y) = sphere_to_square(v)` (Phase 1 kernel, uses `|z|`, so both hemispheres sample the same square position); `x = X*(w-1)`, `y = Y*(h-1)` with `w = h = dim_scaled`; `ix0 = min(floor(x), w-1)`, `iy0 = min(floor(y), h-1)`, `ix1 = min(ix0+1, w-1)`, `iy1 = min(iy0+1, h-1)`; `wx1 = x - ix0`, `wy1 = y - iy0`; value `= img[iy0, ix0]*(1-wy1)*(1-wx1) + img[iy0, ix1]*(1-wy1)*wx1 + img[iy1, ix0]*wy1*(1-wx1) + img[iy1, ix1]*wy1*wx1` (`BiPix::bilinearCoeff/interpolate`; row index from `Y`, column from `X`, matching Phase 1's `normals[j, i] == square_to_sphere(i/(dim-1), j/(dim-1))`). Vectorised NumPy (`dim_leg**2 = 149769` points at bw 384; no numba needed). Equator ring points hit `x == w-1` exactly (`sqrt(1-0) = 1`), where the `min` clamps make the second column weight zero.

### D7 -- Weighted normalisation and the `emsphinx_compatible` quirks (`master.hpp:557-584`)

`w[j, i] = ring_solid_angles(dim_leg, "legendre")[ring_number(dim_leg)[j, i]]` (`square::solidAngles(dim, Legendre)`, `square_sht.hpp:1105-1138`; any constant factor cancels), then the four border lines are halved (`master.hpp:565-568`) -- the corners are hit twice and end up quartered; `totW = sum(w)`;
`mean = (sum(w*north) + sum(w*south)) / D`; `north -= mean; south -= mean`; `std = sqrt((sum(w*north**2) + sum(w*south**2)) / (2*totW))` (`:581`); divide both by `std`.

- `emsphinx_compatible=True` (**default**, parity-first -- decided by the user 2026-08-16): `D = totW` (the 2x-mean quirk, `master.hpp:572-573`; `a_00` ends up at `-sqrt(4 pi) mu/sigma'`, measured **-2.985** for the in-package Ni master and -3.300 for the full one, i.e. 71 % of the total power sits at `l = 0`) and the corners quartered. This is what `mp2sht` does and what the parity fixtures contain, so the default reproduces every existing `.sht` and what `IndexEBSD` indexes with.
- `emsphinx_compatible=False` (opt-in, the corrected normalisation): `D = 2*totW` and the corners halved once (the whole equator ring is shared by the two hemispheres, so every equator pixel is counted twice, corners included). Measured on the Ni masters: `a_00 = -6.3e-5` (401 px) / -5.7e-5 (1001 px), and the coefficients differ from the compatible ones by a **global factor** `sqrt(1 + mu**2/sigma**2)` = 1.854 (401 px) / 2.740 (1001 px) plus a DC shift, rel-L2 after DC removal and rescaling 5.1e-9 -- so the two settings differ *only* in `a_00` and a global scale. This is what EMSphInx's author expected the constructor to produce: `programs/master_xcorr.cpp:75-76` calls `removeDC()` with the comment "it should already be almost zero from nrm == true in construction" -- true for `False` (`-6.3e-5`), false for mp2sht's output and for the default `True` (`-2.985`).

**What the DC term does to indexing (recorded, so the default is a decision and not an accident).** With the *un-normalised* correlator the `l = 0` term of the SO(3) cross-correlation is rotation-independent, so `a_00` and the global factor shift and scale every score equally and orientations are unaffected (mission: those scores are un-normalised, comparable within a fixed geometry). With the *normalised* correlator -- EMSphInx's namelist default (`nml.hpp:209` `normed = true`; `idx.hpp:263-284` builds `sphere::NormalizedCorrelator` when `nml.normed`, else `UnNormalizedCorrelator`) -- the numerator's constant `a_00` contribution is divided by a rotation-dependent denominator (the masked power of the rotated master, `flm2`/`mlm` in `idx.hpp:271-281`), so the master's DC term *can* shift the argmax; and `IndexEBSD` never removes it (`idx.hpp:181-182` only `resize(nml.bw)`; the only `removeDC` callers are `master_xcorr.cpp:75-76`), i.e. every mp2sht `.sht` in existence indexes with `a_00 = -2.985` (71 % of the total power at `l = 0`, D15). Consequences frozen here: (i) the Phase 6/7 parity runs against `IndexEBSD.exe` (mission criterion 2) use the default `emsphinx_compatible=True`; (ii) Phase 4's `validation.md` gets a required gate (constitution amendment, `plan.md` 0.1): a Ni master spectrum rotated by a known `R` (Phase 3 `rotate`) correlated through `NormalizedSphericalCrossCorrelator` with the master in *both* settings, asserting the argmax misorientation stays within the Phase 4 grid/refinement tolerance and recording the score difference -- if it does not, the choice of default (`True`, parity-first, decided by the user 2026-08-16) is revisited before Phase 6; (iii) `save()` does not warn (neither setting warns on every save) but the provenance goes into the file `notes` (D3 step 7) and `describe()` prints `a_00` and `P_0 / sum(P)` (D15), so a kikuchipy-written `.sht` with `a_00 ~ 0` (opt-in `False`) is recognisable to an EMSphInx user; the class `Notes` state that the default `True` reproduces EMSphInx/mp2sht and that `False` is the opt-in corrected normalisation with `a_00 ~ 0`.

Both quirks sit behind the one keyword (constitution: quirks ported faithfully behind explicit per-call keywords, listed in one docs table with their default). `normalize=False` skips step 5 entirely (`nrm=false`); it is exercised by a public-keyword test (validation), because it is the one path on which D5's DCT amplitude factor is observable end to end.

### D8 -- Bandwidth default and the resolution warning

`bandwidth=384` (mp2sht, `mp2sht.cpp:53`). `from_master_pattern` emits `UserWarning` when `bandwidth > (dim - 1)//2` (source Lambert side `dim`): "a 401 px master carries information up to l ~ 200; the bw 384 fixtures exist for mp2sht parity, never for accuracy claims" (`specs/tech-stack.md`). The message names `bandwidth`, `dim` and `(dim-1)//2`. `bandwidth < 1` or `> 32767` (int16 in the file) -> `ValueError`. Recorded: unlike EMSphInx's `"insufficient grid resolution"` (`master.hpp:559`), no error can occur for a Lambert input, because `toLegendre` always resamples to exactly `dim_leg` (the throw only fires for a Legendre input smaller than `dim_leg`, which cannot be built from an `EBSDMasterPattern`); the in-package 13 px `master_patterns.h5` therefore works at any bandwidth (with the warning above bw 6).

### D9 -- Symmetry flags: LUT keyed on orix names, validated against the operators and the coefficients

`_symmetry.Z_ROTATION_ORDER_AND_MIRROR: dict[str, tuple[int, bool]]` with **40 keys**: the 38 `orix.quaternion.symmetry._groups` names (identical on orix 0.12.1 and 0.14.2, verified) plus `"2"` and `"m"`, which are the names of `orix.quaternion.symmetry.C2` (2-fold about **z**, same operators as `"112"`) and `Cs` (mirror **perpendicular to z**, same as `"11m"`) and are what `Phase(space_group=3..5)`/`get_point_group()` return (verified: `Phase(space_group=3).point_group.name == "2"`, `Phase(space_group=6).point_group.name == "m"`; neither string is in `_groups`). Values (EMSphInx `zRot()` via `rotationGroup()`, `symmetry.hpp:1179-1226, 1576-1594`, and `zMirror()`, `:1471-1519`, evaluated on the orix operators):

| names | `n_fold` | `has_equatorial_mirror` |
|---|---|---|
| `1`, `-1`, `211`, `121`, `m11`, `1m1` | 1 | False |
| `11m`, `m` | 1 | True |
| `112`, `2`, `222`, `mm2`, `-4`, `-42m`, `23`, `-43m` | 2 | False |
| `2/m`, `mmm`, `m-3` | 2 | True |
| `4`, `422`, `4mm`, `432` | 4 | False |
| `4/m`, `4/mmm`, `m-3m` | 4 | True |
| `3`, `-3`, `321`, `312`, `32`, `3m`, `-3m` | 3 | False |
| `-6`, `-6m2` | 3 | True |
| `6`, `622`, `6mm` | 6 | False |
| `6/m`, `6/mmm` | 6 | True |

Normative cross-check (a test, not advice): for every key, `n_fold == 1 + #{proper elements g with |axis_z| == 1 and angle > 0}` and `has_equatorial_mirror == any(improper element with |axis_z| == 1 and angle == pi)` computed from the `Symmetry` object (`g[~g.improper]`, `.axis`, `.angle`); note `Symmetry.get_axis_orders()` counts improper elements too (`"2/m"` reports 3 for the z axis) and is not used as the oracle. **Coefficient-consistency guard** (new; not in EMSphInx). One quantity and one tolerance serve both this guard and the `save()` losslessness guard of D11: the **relative power** `sum_{dropped} |a_lm|^2 / sum_{all} |a_lm|^2` with `m > 0` entries counted twice (the `power_spectrum` weighting, D15), and `_symmetry.SYMMETRY_POWER_TOLERANCE = 1e-8` (relative power, i.e. relative amplitude ~1e-4; the D11 guard previously used an amplitude `atol`, which left a four-decade window in which construction passed silently and `save()` hard-failed -- closed by sharing the quantity). At construction, if the LUT claims `n_fold = n > 1` but the relative power in rows `m % n != 0` exceeds the tolerance, `MasterPatternHarmonics` warns (`UserWarning`) and downgrades to the **largest divisor** `d` of `n` (tested in the order `6 -> 3 -> 2 -> 1`, `4 -> 2 -> 1`, `3 -> 1`, `2 -> 1`) whose rows `m % d != 0` are within tolerance, so a 6-fold master that only satisfies 3-fold keeps the 3-fold plane skipping of Phase 4 (`sht_xcorr.hpp:701-705`) instead of losing it; if it claims a mirror but the relative power in `(l + m)` odd entries exceeds the tolerance, `has_equatorial_mirror` becomes `False`. The comparison is `<=` (a relative power of `0.9e-8` passes, `1.1e-8` fails). Measured on the Ni masters: 5.7e-32 and exactly 0. Motivation (recorded, verified): orix maps monoclinic space groups 3-15 to z-unique groups (`"2"`, `"m"`, `"2/m"`), whereas EMSphInx (`SG2PG`, `symmetry.hpp:404-475`) and the SHTfile LUTs assume unique axis **b**, so a b-unique monoclinic master would carry a wrong `fNf = 2`/`fMr = True` into the Phase 4 correlator with no error -- the guard turns that into a warning and a safe `(1, False)`.

The `.sht` `zRot`/`cmpFlg` (D10) are **never** derived from this table (critique m12); they come from `SpaceGroupRot`/`SpaceGroupCmp` and are kept in `_sht_file.py`.

### D13 -- `to_master_pattern()` = direct Lambert synthesis (replaces `toLambert`)

`dim = 2*bandwidth + 1` by default (the Lambert grid whose `max_bandwidth(dim, "lambert") == bandwidth`, Phase 1: 769 for bw 384); `dim` must be odd `>= 3`. If `(dim-1)//2 < bandwidth` the coefficients are cropped to `(dim-1)//2` (a band limit) with a `UserWarning`. `north, south = SphericalHarmonicTransform(bw_used, "lambert", dim).synthesize(alm[:bw_used, :bw_used])` -> `EBSDMasterPattern(np.stack([north, south]) or one of them, phase=self.phase, projection="lambert", hemisphere=...)` (`hemisphere in {"upper", "lower", "both"}`, `"lower"` = south alone, else `ValueError` listing the options) with axes `hemisphere` (if both), `height`, `width` (offsets **`-(dim//2)`**, units px, `original_metadata` = the D10 `metadata_dict()`) and `metadata.General.title = phase.name`, float64. **Axis-offset convention (deliberate, recorded)**: `-(dim//2)` centres the axis on the middle pixel (`-384` for 769, `-200` for 401), as the ebsdsim reader does (`ebsdsim_master_pattern/_api.py:206, 216`, `-(side // 2)`), whereas kikuchipy's EMsoft reader writes `-sy // 2` (`_emsoft_master_pattern.py:186`; Python floor division, `-201` for 401, `-385` for 769 -- one pixel off centre for every odd side; verified: `nickel_ebsd_master_pattern_small(projection="lambert", hemisphere="both")` has height/width offset `-201.0`). The centred convention is chosen and the one-pixel difference is asserted in the io test (`to_master_pattern(dim=401)` offset `-200` vs the source master's `-201`), so a user comparing the two knows which is intended; no computation reads these offsets (`get_patterns` scales by `(dim-1)//2`). Rationale, measured: EMSphInx's `sht2png` route (synthesize on Legendre, then `toLambert` = nearest neighbour among four bounding Legendre points, `master.hpp:423-473`, "in the future this should probably switch to barycentric") is strictly worse than sampling the band-limited function on the Lambert nodes, which `synthesize` does exactly (Phase 1 synthesize oracle 1e-11). Determinations on the mp2sht coefficients of the in-package Ni master: Pearson `r` of the synthesized north hemisphere vs the source **0.9963** at `dim = 769` (source bilinearly upsampled), **0.9704** at `dim = 401` (cropped to bw 200), 0.889 at 201, 0.621 at 101; `EBSDMasterPattern.get_patterns` on the `dim = 769` result vs the same call on the source master: NCC **0.9963-0.9974** over three rotations (0.978-0.982 at `dim = 401`), which also confirms the hemisphere/axis conventions end to end (critique 29). Requires the `_sht.py` amendment: `SphericalHarmonicTransform` computes `quadrature_weights` lazily (cached on first access/`analyze`), since only `analyze` needs them (`_synthesize_numba`/`_synthesize_rfft` take no weights, `_sht.py:491-503, 672-680`) and `quadrature_weights(769, "lambert")` would trip the Sneeuw guard (Phase 1: first tripping `dim` 277). Phase 1's `test_lambert_weights_raise_at_dim_401` (on the `_grid` function) is unaffected; any Phase 1 test that asserts the *constructor* raises for large Lambert `dim` moves to `analyze`.

### D19 -- Recorded deviations from EMSphInx (all deliberate)

1. Reader accepts opaque simulation records and `numXtal != 1` at the codec level (D10); harmonics level raises `NotImplementedError`.
2. `energy_weights` for a loaded energy subset are renormalised over the loaded bins (D4).
3. The opt-in `emsphinx_compatible=False` computes the mean over `2*totW` and halves corners once (D7), so a `.sht` written with it carries `a_00 ~ 0` where every mp2sht file carries `a_00 = -2.985`; the default `True` (parity-first, decided by the user 2026-08-16) reproduces mp2sht bit-for-bit up to FFT/LAPACK rounding and is what the `IndexEBSD.exe` parity runs use. The provenance is written into the file `notes` (D3 step 7).
4. `to_master_pattern` synthesizes on the Lambert grid instead of nearest-neighbour `toLambert` (D13); its axis offsets are centred (`-(dim//2)`), one pixel off kikuchipy's EMsoft reader (`-sy // 2`) for odd sides (D13).
5. Symmetry-flag and packing guards (D9, D11) that EMSphInx does not have: `save(strict=True)` refuses what `PackHarm` would silently drop; `strict=False` is EMSphInx's behaviour with a warning.
6. `describe()` is not a byte copy of `sht2png`'s stdout format (and adds `a_00`/DC power fraction).
7. `emsoftVersion = "unknown"` instead of the hard-coded `5_0_0_0`; `softwareVersion` is a NUL-padded kikuchipy tag; crystal `name` is written (mp2sht writes ""); `notes` records the normalisation.
8. Two-sided guard etc. of Phase 1 apply unchanged (Legendre analysis at bw 384/dim 387 is on the `scipy.fft` path).
9. `from_master_pattern` refuses integer multi-site masters that kikuchipy's EMsoft reader has summed in the file dtype (D3), where EMSphInx (float32 accumulation) would proceed.
10. Non-EBSD/opaque simulation records are only length-checked on write (D10), where EMSphInx would refuse to construct them.
